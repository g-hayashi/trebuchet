# プライベート会計ソフト 要件定義 v0.2

- 作成: 2026-10-17。状態の更新: 2026-10-25
- 根拠資料: work/ 配下の実データ（freee の帳簿、過去の申告書類、請求書）
- **状態の見方**: 各要件の見出し（FR）と表の「状態」列（NFR）に、実装の状態を書く。「済 00N」は `specs/00N-*/` で実装済み、「一部済」は残りを併記、「保留」は着手を止めている、「未着手」は仕様がない。不変条件の索引は `specs/INVARIANTS.md`

## 1. 背景と前提

| 項目 | 内容 |
|---|---|
| 事業 | 受託の役務提供。時間単価×稼働時間が中心、月額定額あり |
| 申告 | 青色申告 65万円控除（e-Tax）。事業所得以外は計算対象外 |
| 消費税 | 現在は免税・インボイス未登録。将来の登録やマイクロ法人化に備え、**事業体×期間で課税区分を切替** |
| 現行環境 | 会計＝freee、明細集約＝MF ME 無料版（個人用。**事業用と私用のカードが混在**）、請求書＝Misoca（こだわりなし） |
| 口座 | 個人口座1つで事業収入と私用が混在。クレカの引落もこの口座 |

## 2. 機能要件

優先度: P1＝並行稼働に必須、P2＝早期、P3＝後回し可

### FR-01 事業体（テナント）— P1 — 状態: 済 001
- 個人事業と法人を別テナントとして扱い、**DBファイルを分離**する。テナント間の集計・参照はしない
- 法人固有の機能（法人税、別表など）は P3。データ構造は勘定科目体系の差し替えだけで対応できるようにする

### FR-02 勘定科目・マスタ — P1 — 状態: 済 001
- 勘定科目（決算書の表示名・欄番号の対応つき）、補助科目（口座・カード）、取引先、メモタグ
- 部門・品目・セグメントは持たない（3年間とも未使用）

### FR-03 仕訳 — P1 — 状態: 済 001
- 手動入力（複合仕訳を含む）。仕訳単位で貸借の一致を必須にする
- 金額は整数（円）。税額は税込経理・内税・切り捨てを既定にする
- **物理削除は不可**。締め前の年度は変更前の内容を履歴に残して訂正し、締め済みの年度は当年度に訂正仕訳を起票する（電子帳簿保存法）

### FR-04 定期仕訳・家事按分 — P2 — 状態: 済 005（定期仕訳）、済 003（家事按分。決算整理の仕訳として登録する）
- 月次の定期仕訳を自動登録する（地代家賃・水道光熱費・通信費など）
- 家事按分：科目ごとに按分率と根拠メモを設定し、年度ごとに履歴を残す。私用分は事業主貸へ自動で振り替える。対象は家賃・通信費・水道光熱費など

### FR-05 工数・請求 — P2 — 状態: 済 005（源泉徴収・仮払税金は P3、未着手）
- 取引先マスタ：単価、敬称（様／御中）、支払期限の規則（既定は翌月末、取引先ごとに翌月10日など）、請求の型（時間単価型／月額定額型）
- 月末に工数を手入力する（0.5時間単位）→ 請求書を作成（明細は最大数行、空行は出力しない）→ PDF出力 → 売掛金／売上高 を仕訳
- 請求番号は `YYYYMMDD-NNN`（発行日と取引先をまたいだ通し番号）。番号の重複は不可
- 消費税の表示（別記／税込のみ）は**設定で切替**。登録番号の欄は設定時のみ表示
- 入金は手動で売掛金に消し込む。源泉徴収の計算・仮払税金の処理は P3

### FR-06 明細取込（MF ME）— P2 — 状態: 一部済 006（貼り付けによる取込、冪等、事業／私用、カードの引落・振替の仕訳化）。MF ME の画面からの取得は取りやめ（2026-10-26 利用者の判断。実装は削除）。汎用の明細取込は 007
- Playwright で MF ME の画面から明細を取得する（規約上のリスクは承知のうえ。2段階認証は手動で介入する）
- 取込の冪等性：明細ごとに安定したキーで重複を防ぐ
- **事業／私用の判定**をAIの仕訳推定に含める。私用は取り込まないか、事業主貸として処理する
- カードの引落（未払金／普通預金）も仕訳化する

### FR-07 AI仕訳 — P2 — 状態: 済 006（ADR 0009。ルール → 端末内 `fm` → 外部の AI の順、承認してから登録、評価。証憑からの推定は FR-08 とともに未着手）
- 明細・証憑から仕訳候補（科目・税区分・取引先・事業／私用・確信度）を構造化して出力し、**人が承認してから登録**する
- 推定の順序：ルール（過去の確定仕訳から学習した一致ルール）→ ローカルLLM（macOS の `fm`）→ クラウドLLM（確信度が低いときのみ）
- 精度を評価するデータセット（Evals）を過去の仕訳から作る

### FR-08 証憑（領収書・レシート）— P2 — 状態: 未着手（Tailscale 経由のアップロードは NFR-02 の保留に依存。006 の範囲を先に決める）
- スマホで撮影し、Tailscale 経由のPWAからアップロードする
- 画像を保存し、OCRとAIで仕訳候補を作る。仕訳と証憑を紐づける
- 電子帳簿保存法（スキャナ保存・電子取引）の検索要件：取引年月日・金額・取引先で検索できること

### FR-09 帳票 — P1 — 状態: 済 001
- 仕訳帳、総勘定元帳、試算表、損益計算書（PL）、貸借対照表（BS）。期間を指定でき、前年と比較できる

### FR-10 決算・確定申告支援 — P2（2027年2月までに）— 状態: 一部済 003（決算書の表示、按分、少額減価償却資産の特例、控除の判定）、済 002（年初付の決算振替は期首残高へ繰り込む。ADR 0004）。未着手: 一括償却・定額法、開業費の償却の計算（知らせのみ）
- 決算振替：翌年1/1付で事業主貸・事業主借・利益を元入金へ振り替える
- 固定資産台帳：少額減価償却資産の特例、一括償却、定額法を扱う。基準額などは税制ルールのデータから取得する
- 繰延資産（開業費）を管理する
- 青色申告決算書（1〜4ページ）の数値を表示する：月別売上、売上先別（合計が売上と不一致なら警告）、地代家賃の内訳、減価償却の明細、BS。作成コーナーへの転記用
- 65万円控除の要件チェック
- 検証：前期末と当期首の残高の継続性、負の売掛金、貸借の一致
- 事業所得以外の控除などはメモ欄のみ（金額と証明書の保管場所を記録）

### FR-11 税制更新フォロー — P3 — 状態: 一部済 003（適用期間・出典つきの税制の表）。未着手: AI による更新の調査と差分の提案
- 税率、少額資産の基準額、控除額などを**適用開始日つきのデータ**として版管理する
- AIが国税庁などの更新を調べて差分を提案し、人が承認して反映する

### FR-12 移行・並行稼働 — P1 — 状態: 済 002
- freee の仕訳帳（汎用形式, UTF-8, 103列）と総勘定元帳（CP932）をインポートする
- 冪等キーは `仕訳ID`＋`仕訳行番号`、変更の検知は `更新日時` で行う。再取込時は上書き更新（upsert）
- 2026年の開始残高は freee の値をそのまま採用し、R6→R7 の差異はメモで管理する
- 1/1付の決算仕訳は二重計上しないように区別する
- 取込後に、元帳の科目別の合計・残高と自動で突合する

## 3. 非機能要件

| ID | 区分 | 要件 | 状態 |
|---|---|---|---|
| NFR-01 | 稼働形態 | Mac 上のローカルWebアプリ。後で Tauri 化する。公開ホスティングはしない | 済 001（Tauri 化は未着手） |
| NFR-02 | リモート | Tailscale 経由でアクセスする（スマホを含む）。HTTPS は `tailscale serve` で提供する | 保留（004 の US4、2026-10-24） |
| NFR-03 | 認証 | パスキー（Touch ID）。WebAuthn には secure context が必要 | 済 004（ADR 0006） |
| NFR-04 | 保存 | SQLite（テナントごとにファイル）。証憑は内容ハッシュをファイル名にして保存する | 一部済 001（SQLite）。証憑は未着手 |
| NFR-05 | 改ざん防止 | 物理削除なし。変更履歴は追記のみ。操作ログを残す | 済 001（以降の機能も追記のみの記録を持つ） |
| NFR-06 | バックアップ | 利用者が選んだ同期フォルダへ暗号化して置く。**ユーザーが指定したパスフレーズで暗号化**する。忘れると復元できないことを明示する。復元手順をテストする | 済 004（ADR 0007） |
| NFR-07 | AI | プロバイダを抽象化する（ローカルの `fm`／クラウド）。出力はスキーマで検証する。送信する情報は最小限にし、個人情報はマスクする | 済 006（ADR 0009。利用名に混じる個人名は伏せきれない限界がある） |
| NFR-08 | 正確性 | 金額は整数で計算する。貸借一致などの不変条件をプロパティベーステストで検証する | 済 001〜005（`specs/INVARIANTS.md`） |
| NFR-09 | 保存期間 | 帳簿・証憑は7年以上保存する | 一部済 004（バックアップの世代は 7 年）。証憑は未着手 |
| NFR-10 | 性能 | 仕訳 数千件/年で、帳票を1秒以内に表示する | 済 001（`pnpm bench:reports`） |

## 4. 技術スタック（確定）
TypeScript / Vite + React / Hono / SQLite + Drizzle / Zod / Vitest + fast-check / Playwright / Spec Kit

## 5. 開発の進め方（学習テーマ）
- 仕様駆動開発：Spec Kit で constitution → spec → plan → tasks → 実装
- AIエージェント開発：Claude Code と AGENTS.md
- プロパティベーステスト：fast-check で会計の不変条件を検証する

## 6. 開発フェーズ（案）
1. **基盤**：テナント、マスタ、仕訳、帳票、freee 取込、認証、バックアップ（FR-01〜03, 09, 12）
2. **日常業務**：定期仕訳、家事按分、工数と請求書（FR-04, 05）
3. **自動化**：MF ME 取込、AI仕訳、証憑（FR-06〜08）
4. **決算**：決算整理と決算書の表示（FR-10）。2026年分の申告に間に合わせる
5. **拡張**：税制更新、法人テナント、源泉徴収（FR-11 など）

## 7. 未決事項・リスク
- MF ME のスクレイピング：規約、画面変更、2段階認証。取得できない場合は手動でCSVを取り込む代替手段を用意する
- 少額減価償却資産の基準額の改正（個人への適用）を確認する
- 電子帳簿保存法のスキャナ保存の詳細要件（解像度など）は、仕様化の時点で国税庁の資料で確認する
- work/ には個人情報と顧客資料が含まれるため、**Git 管理の対象から外す**
