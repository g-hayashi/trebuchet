# プライベート会計ソフト 要件定義 v0.2

- 作成: 2026-10-17。状態の更新: 2026-11-08
- 根拠資料: work/ 配下の実データ（freee の帳簿、過去の申告書類、請求書）
- **状態の見方**: 各要件の見出し（FR）と表の「状態」列（NFR）に、実装の状態を書く。「済 00N」は `specs/00N-*/` で実装済み、「一部済」は残りを併記、「保留」は着手を止めている、「未着手」は仕様がない。不変条件の索引は `specs/INVARIANTS.md`

## 1. 背景と前提

割愛

## 2. 機能要件

優先度: P1＝並行稼働に必須、P2＝早期、P3＝後回し可

### FR-01 事業体（テナント）— P1 — 状態: 済 001
- 個人事業と法人を別テナントとして扱い、**DBファイルを分離**する。テナント間の集計・参照はしない
- 法人固有の機能（法人税、別表など）は P3。データ構造は勘定科目体系の差し替えだけで対応できるようにする

### FR-02 勘定科目・マスタ — P1 — 状態: 済 001
- 勘定科目（決算書の表示名・欄番号の対応つき）、補助科目（口座・カード）、取引先、メモタグ
- 部門・品目・セグメントは持たない（3年間とも未使用）

### FR-03 仕訳 — P1 — 状態: 済 001
- 手動入力（複合仕訳を含む）。仕訳単位で貸借の一致を必須にする
- 金額は整数（円）。税額は税込経理・内税・切り捨てを既定にする
- **物理削除は不可**。締め前の年度は変更前の内容を履歴に残して訂正し、締め済みの年度は当年度に訂正仕訳を起票する（電子帳簿保存法）

### FR-04 定期仕訳・家事按分 — P2 — 状態: 済 005（定期仕訳）、済 003（家事按分。決算整理の仕訳として登録する）
- 月次の定期仕訳を自動登録する（地代家賃・水道光熱費・通信費など）
- 家事按分：科目ごとに按分率と根拠メモを設定し、年度ごとに履歴を残す。私用分は事業主貸へ自動で振り替える。対象は家賃・通信費・水道光熱費など

### FR-05 工数・請求 — P2 — 状態: 済 005・013（源泉徴収）
- 取引先マスタ：単価、敬称（様／御中）、支払期限の規則（既定は翌月末、取引先ごとに翌月10日など）、請求の型（時間単価型／月額定額型）
- 月末に工数を手入力する（0.5時間単位）→ 請求書を作成（明細は最大数行、空行は出力しない）→ PDF出力 → 売掛金／売上高 を仕訳
- 請求番号は `YYYYMMDD-NNN`（発行日と取引先をまたいだ通し番号）。番号の重複は不可
- 消費税の表示（別記／税込のみ）は**設定で切替**。登録番号の欄は設定時のみ表示
- 入金は手動で売掛金に消し込む。源泉徴収税額は請求書に載せ、入金の時点で事業主貸に計上する（013）

### FR-06 明細取込（MF ME）— P2 — 状態: 済 006（貼り付けによる取込、冪等、事業／私用、カードの引落・振替の仕訳化）・007（汎用の明細取込: 貼り付けと CSV などのファイル、取込元を問わない読み取り、列の対応の保存と自動の当てはめ、端末内の AI による列の案。ADR 0010）。MF ME の画面からの取得は取りやめ（2026-10-26 利用者の判断。実装は削除）。007 の利用者の端末での確認（T021）は済
- 銀行・カードなどの明細を、貼り付けまたは CSV などのファイルで取り込む（取込元を問わない。列の対応は見出しごとに覚える。007）。銀行の自動連携や画面からの取得はしない
- 取込の冪等性：明細ごとに安定したキーで重複を防ぐ
- **事業／私用の判定**をAIの仕訳推定に含める。私用は取り込まないか、事業主貸として処理する
- カードの引落（未払金／普通預金）も仕訳化する

### FR-07 AI仕訳 — P2 — 状態: 済 006（ADR 0009。ルール → 端末内 `fm` → 外部の AI の順、承認してから登録、評価。証憑の画像からの値の読み取りは 010 の外部の AI〔ADR 0014〕）。端末内の AI は非推奨で既定は無効（2026-11-07 利用者の判断。全項目一致が 0%。外部の AI を推奨。有効にすれば使える。無効だと列の案〔007〕も出ない）
- 明細・証憑から仕訳候補（科目・税区分・取引先・事業／私用・確信度）を構造化して出力し、**人が承認してから登録**する
- 推定の順序：ルール（過去の確定仕訳から学習した一致ルール）→ ローカルLLM（macOS の `fm`）→ クラウドLLM（確信度が低いときのみ）（現状は状態欄のとおり）
- 精度を評価するデータセット（Evals）を過去の仕訳から作る（現状は状態欄のとおり。アプリの中の評価は 011 で `pnpm eval:statements` に移した）

### FR-08 証憑（領収書・レシート）— P2 — 状態: 済 010（ADR 0014。画像・PDF の暗号化した保存、取引年月日・金額・取引先の検索、仕訳との結びつき、外部の AI による値の候補〔OCR の代わり。利用者が別に有効にしたときだけ。憲法 III の例外〕、訂正・差し替え・削除の履歴、スマホの撮影の画面、バックアップと復元。紙を撮影した証憑は紙の原本も保存する）。利用者の端末での確認（T041〜T044: 画面の手動確認、評価用の画像と外部の AI の評価、スマホの実機。実機は NFR-02 の 004 の US4 の確認の後）は済
- スマホで撮影し、Tailscale 経由のPWAからアップロードする
- 画像を保存し、OCRとAIで仕訳候補を作る。仕訳と証憑を紐づける（現状は状態欄のとおり。OCR の代わりに外部の AI で値の候補を読む）
- 電子帳簿保存法（スキャナ保存・電子取引）の検索要件：取引年月日・金額・取引先で検索できること

### FR-09 帳票 — P1 — 状態: 済 001
- 仕訳帳、総勘定元帳、試算表、損益計算書（PL）、貸借対照表（BS）。期間を指定でき、前年と比較できる

### FR-10 決算・確定申告支援 — P2（2027年2月までに）— 状態: 済 003（決算書の表示、按分、少額減価償却資産の特例、控除の判定）・009（定額法、一括償却資産、開業費の償却の決定、固定資産台帳と帳簿の照合。ADR 0012）、済 002（年初付の決算振替は期首残高へ繰り込む。ADR 0004）
- 決算振替：翌年1/1付で事業主貸・事業主借・利益を元入金へ振り替える
- 固定資産台帳：少額減価償却資産の特例、一括償却、定額法を扱う。基準額などは税制ルールのデータから取得する
- 繰延資産（開業費）を管理する
- 青色申告決算書（1〜4ページ）の数値を表示する：月別売上、売上先別（合計が売上と不一致なら警告）、地代家賃の内訳、減価償却の明細、BS。作成コーナーへの転記用
- 65万円控除の要件チェック
- 検証：前期末と当期首の残高の継続性、負の売掛金、貸借の一致
- 事業所得以外の控除などはメモ欄のみ（金額と証明書の保管場所を記録）

### FR-11 税制更新フォロー — P3 — 状態: 済 003（適用期間・出典つきの税制の表）
- 税率、少額資産の基準額、控除額などを**適用開始日つきのデータ**として版管理する

### FR-12 移行・並行稼働 — P1 — 状態: 済 002
- freee の仕訳帳（汎用形式, UTF-8, 103列）と総勘定元帳（CP932）をインポートする
- 冪等キーは `仕訳ID`＋`仕訳行番号`、変更の検知は `更新日時` で行う。再取込時は上書き更新（upsert）
- 2026年の開始残高は freee の値をそのまま採用し、R6→R7 の差異はメモで管理する
- 1/1付の決算仕訳は二重計上しないように区別する
- 取込後に、元帳の科目別の合計・残高と自動で突合する

### FR-14 アプリ内マニュアル — P1 — 状態: 済 012

目的別の操作手順、番号付きの実画面キャプチャ、注意事項、FAQをアプリ内で参照する。全画面から開け、入力中の内容とURLを保持する。目的・ボタン名・エラーで検索でき、施錠中も説明を読める。記事と画面・処理の対応を記録し、CIで更新漏れを検知する。再撮影はコマンドで自動化し、本文の内容確認後に確認版を更新する。自動の文章生成・外部公開は行わない。詳細は `docs/features/012-app-manual.md`。

### FR-15 デモ事業 — P2 — 状態: 済 014
- 事業体の一覧が空のとき「デモ事業を作って試す」ボタンを出し、押したときだけ作る（自動では入れない。2026-11-08 利用者の判断）
- データは機能が一通り試せる範囲（期首残高、取引先、仕訳と訂正・取消、家事按分、固定資産・開業費、定期仕訳、請求と入金〔源泉徴収〕、証憑、未処理の明細）。決算整理の登録と締めは利用者が試す
- 日付は起動した年に合わせる。デモと分かる目印を付け、試し終わったら削除（既存のアーカイブ・完全削除）を案内する。証憑の画像と明細は製品に同梱する合成の素材（テストのフィクスチャを参照しない）。AI は呼ばない

### FR-16 画面からの復元 — P2 — 状態: 未着手（015 の予定）
- 今はバックアップ（`.tbk`）の復元がコマンド（`pnpm restore`）だけで、画面は検査まで。新しい Mac に移るときに端末の操作なしで戻せるよう、初回起動（帳簿がない状態）の画面から復元できるようにする
- データ場所の入れ替えと鍵（回復キー）を扱うため、014 とは別の機能にする

## 4. 技術スタック（確定）

## 5. 開発の進め方（学習テーマ）

## 6. 開発フェーズ（案）
1. **基盤**：テナント、マスタ、仕訳、帳票、freee 取込、認証、バックアップ（FR-01〜03, 09, 12）
2. **日常業務**：定期仕訳、家事按分、工数と請求書（FR-04, 05）
3. **自動化**：MF ME 取込、AI仕訳、証憑（FR-06〜08）
4. **決算**：決算整理と決算書の表示（FR-10）。2026年分の申告に間に合わせる
5. **拡張**：法人テナント
