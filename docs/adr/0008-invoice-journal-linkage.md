# ADR 0008: 請求書・入金は仕訳と同じトランザクションで作り、通常の訂正・取消から守る

- 状態: 採用
- 日付: 2026-10-25
- 関連: specs/005-recurring-invoicing/research.md R9, R12, R13、ADR 0003

## 状況

請求書の発行は、売上の仕訳・請求番号・請求書・明細・操作の記録を書く。入金の消し込みは、入金の仕訳と消し込みの行を書く。どれか 1 つだけが残ると、請求書の合計と売上の仕訳が食い違う。また、利用者が 001 の画面から請求・入金の仕訳を直接訂正・取消すと、請求書は残ったまま仕訳だけが変わる。

drizzle のトランザクションは、コールバックが `err`（Result の失敗）を返しても確定する。巻き戻すのは例外のときだけである。

## 決定

- **1 つのトランザクションで書く**。発行は「仕訳 → 通し番号 → 請求書 → 明細 → 操作の記録」の順。最初の書き込みを 001 の `createJournal` / `voidJournal` にし、その `err` はそのまま返す（仕訳の関数は検査の後に書くので、何も残らない）。以降の失敗とドメインの判断での中止は `RollbackError`（`DomainError` を持つ例外）を投げて全体を巻き戻し、ユースケースの外側で `err` に直す。読み取りと検査は、書き込みの前にすべて済ませる
- **発行時の写しを持つ**。請求書は発行者・宛名・敬称・税の表示・支払期限・明細を自分の行に写す。後で設定や取引先を変えても、発行済みの請求書は変わらない。写しの列と明細は DB のトリガーで更新を止め、取消で書けるのは取消の列だけにする。物理削除しない
- **通常の訂正・取消を禁止する**。`source` が `invoice` / `payment` の仕訳は、001 の `PUT /journals/:id`・`POST /journals/:id/void` で 409 `JOURNAL_LINKED` を返す。請求・入金の取消だけが `{ linked: true }` で仕訳を取り消す。訂正仕訳の訂正元にできるのは、同じ `source` の仕訳だけ。`recurring` の仕訳は通常の仕訳と同じく訂正・取消できる
- **取消の規則**。理由は 001 の `checkReason`。
  - 元の仕訳の日付の期間が未締め: 仕訳の取消（ADR 0003）
  - 締め済み: 今日付の逆仕訳（訂正仕訳。元の仕訳の貸借を逆にし、`source` は元と同じ）。今日の期間がない・締め済みなら `OUT_OF_PERIOD` / `PERIOD_CLOSED`
  - 消し込み（取消でないもの）がある請求書は、409 `INVOICE_HAS_PAYMENTS` で取消せない。先に消し込みを取り消す

## 理由

- 請求の合計と売上の仕訳の一致を、利用者の注意ではなく構造で守れる
- 仕訳の関数を先に呼ぶ順序なら、検査に落ちたときに何も書かれず、後の失敗は例外で巻き戻せる。001 の関数をそのまま使えるので、仕訳の検証（貸借一致、期間、税）を重複して書かない
- 帳簿の取消は ADR 0003 の方針（未締めは直接、締め済みは訂正仕訳）に揃える。締めた期間の帳簿は後から変わらない

## 検討した代替案

- 訂正・取消を許して、請求書との不一致を警告する: 合計と仕訳の一致（SC-002）を満たせない
- 請求書の項目を、参照先の設定・取引先から都度読む: 設定を変えると発行済みの請求書の内容が変わり、再印刷の結果が変わる
- ユースケースが `err` を返して巻き戻す: drizzle は確定してしまうので、仕訳だけが残る

## 影響

- 請求・入金のユースケースは、読み取りと検査 → 仕訳の関数 → 例外で巻き戻せる書き込み、の順序を守る。順序を変えるときは、障害の注入のテスト（明細の保存で例外）で確かめる
- 001 の `createJournal` は `options.source`、`voidJournal`・`correctJournal` は `options.linked` を受け取る
- server のルート層が `JOURNAL_LINKED` に請求書・入金の ID を補う。domain の関数は `journalId` だけを返す
- 請求書の画面と印刷は、写しの列だけを使う
