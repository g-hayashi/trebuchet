# ADR 0003: 仕訳の訂正・取消は、未締めの期間では直接書き換え、締め済みの期間では訂正仕訳で行う

- 状態: 採用
- 日付: 2026-10-18
- 関連: specs/001-ledger-core/research.md R11、spec.md（US3、FR-019〜025、Assumptions）、data-model.md §3・§5

## 状況

仕訳に誤りがあったとき、直し方を決める必要がある。候補は次の 3 つ。

- 直接書き換える: 帳簿の見た目は正しく保たれる。ただし、過去の内容が残らない
- 打ち消す仕訳（逆仕訳）だけで直す: 履歴は残るが、帳簿を見ると同じ取引が複数行に分かれ、読みにくい
- 締め済みの期間も含めて書き換える: 申告済みの帳簿が後から変わる

締めた期間の帳簿は、申告の根拠として後から変わらないことが求められる。一方、締めていない期間では通常の修正を素直に行いたい。

## 決定

**C 案**（2026-10-18 に決定）:

1. **未締めの期間の仕訳**: その場で書き換える（訂正、`correctJournal`）。変更前の全内容（日付、メモ、行、タグ）と理由を `audit_log` に残す（`action = correct`、`before_json` に変更前の仕訳全体）。
2. **締め済みの期間の仕訳**: 書き換えない。現在の未締めの期間に、元の仕訳を指す**訂正仕訳**を起票する（`corrects_journal_id`）。元の仕訳から訂正仕訳を、訂正仕訳から元の仕訳をたどれる。
3. **取消**: 理由を添えて `status` を `voided` にする。行は残す。物理削除はしない（DB のトリガーで禁止）。
4. **締めの解除（再開）**: 理由が必須。`audit_log` に残す。申告内容の修正など、例外的な場合に限る想定。
5. `audit_log` は追記のみ。`UPDATE` と `DELETE` はトリガーで禁止する（INV-9）。仕訳の変更と監査ログへの追記は、同じトランザクションで行う。

## 理由

- 未締めの期間は、直接書き換えでも `before_json` で変更前の内容が残るため、履歴の要件を満たせる
- 締め済みの期間は、元の仕訳を変えないため、申告済みの帳簿の内容が変わらない。訂正は現在の期間の仕訳として残るので、いつ誤りに気づいて直したかが分かる
- 電子帳簿保存法の訂正・削除の履歴に関する要件は、履歴を保持することで満たす方針（research R11）。法令の解釈は本 ADR の対象外
- 単独利用のため、操作者の記録は持たない（spec.md Assumptions）

## 検討した代替案

- 逆仕訳だけで直す: 履歴は残るが、誤った仕訳と打ち消す仕訳が並び、帳簿を読みにくくする（research R11 で却下）
- 締め済みの期間も直接書き換える: 申告済みの帳簿の内容が後から変わる（research R11 で却下）

## 影響

- 訂正は仕訳の行をすべて置き換える（data-model §3）。`version` を 1 増やし、楽観ロックで競合を検出する
- 締め済みの期間の仕訳は、訂正・取消の対象にできない（`PERIOD_CLOSED`）。ドメインのエラーは訂正仕訳を案内する
- 訂正仕訳の日付が締め済みの期間にあれば、起票できない（`PERIOD_CLOSED`）
- `audit_log` の `before_json` には行とタグを含む全内容が入るため、サイズは仕訳の行数に比例して増える
- 監査ログの追記のみは、DB のトリガーで機械的に保証する。アプリ側の規約に頼らない
- 訂正では、訂正元の仕訳で使っていた科目と補助科目が使用停止になっていても、訂正後の仕訳に残せる（`correctJournal` の `allowUsedAccounts`）
