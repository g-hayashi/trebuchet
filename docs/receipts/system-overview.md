# 電子計算機処理システムの概要書（証憑の保存・検索）

自社開発のプログラム（trebuchet の「証憑」の機能）を電子取引の保存に使うときに備え付ける、システムの概要書（電子帳簿保存法施行規則第2条第2項第一号イ）。訂正・削除の防止の運用は [processing-rules.md](./processing-rules.md)（事務処理規程）にある。

## 保存の仕組み

1. **保存するもの**: 証憑（領収書・レシートなど）のファイル（JPEG・PNG・HEIC・PDF。1 件 20 MB まで）と、取引年月日・金額・取引先・区分・メモ。形式はファイルの中身で判定し、拡張子は見ない。
2. **場所**: 利用者の Mac のデータ場所の下 `receipts/<事業体>/`。サーバーは利用者の Mac の中（`127.0.0.1`）だけで動き、帳簿・証憑を外部のサービスに保存しない。スマホからはペアリングした Tailscale 経由で追加できる（経路は記録される）。
3. **暗号化と名前**: ファイルは、帳簿のデータ鍵（パスキーまたは回復キーで解錠したときだけ使える）から作った鍵で、ファイルごとに AES-256-GCM で暗号化する。ファイル名は元のファイルの SHA-256 ハッシュ（`<ハッシュ>.trc`）。読み出すときは、復号（改ざんの検出）と、ハッシュの一致を確かめる。施錠中は読み書きできない。
4. **追加**: 追加すると、ハッシュ・受領日時・元の名前・形式・大きさ・経路を記録する。同じ内容は 1 件にまとめる（重複は拒む）。ファイルと記録は、全部書けたときだけ残る（途中で失敗すれば残さない）。
5. **訂正・削除の防止（ヴァージョン管理）**:
   - ファイルは版ごとに別の行で保存し、書き換えない。最初に読み取ったファイルが初版として残る。差し替えは新しい版を足す。
   - 値の変更・差し替え・削除・仕訳との結びつけ・解除は、日時・操作・前後の値（差し替えはファイルのハッシュ）・理由を、追記だけの履歴に記録する。既に入力した値の訂正・差し替え・削除・付け替え・解除は、理由が要る。
   - 削除は論理削除で、記録・ファイル・履歴は残る。削除済みも検索・表示・取り出しができる。データベースのトリガーが、証憑・ファイル・結びつき・履歴の物理削除と、ファイル・履歴の書き換えを止める。
   - 履歴をたどると、任意の時点の値と原本を確認できる。
6. **帳簿との結びつき**: 証憑は仕訳に結びつけられる（1 件の仕訳に複数、1 件の証憑に有効な結びつきは 1 件まで）。仕訳の訂正では結びつきが残り、取消では「仕訳が取り消された」と表示される。
7. **検査の警告**: 紙を撮影した証憑は、入力期間（事務処理規程の⑦）と画像の大きさ・色の目安を調べ、外れていれば警告を出す（保存は拒まない）。
8. **証憑の AI 読み取り**: 外部の AI の設定を明示的に有効にしたときだけ、利用者の操作で画像（位置情報を除く）を外部に送る。結果は候補で、利用者が確かめた値だけを保存する。既定は無効（送らない）。

## 検索

1. 証憑の一覧の画面（および API の `GET /receipts`）で、次の条件を指定できる。複数の条件は AND（すべてに合うもの）で組み合わせる。
   - 取引年月日の範囲（日付の範囲指定）
   - 金額の範囲（書類に書かれた税込の金額）
   - 取引先（部分一致。全角・半角、大文字・小文字、空白を区別しない）
   - 区分（電子で受け取ったもの / 紙を撮影したもの）
   - 未入力（取引年月日・金額・取引先のどれかが空）。空欄の書類を探せる
   - 仕訳との結びつき（なし / あり / 仕訳が取り消された）
   - 削除済みを含める
2. 並びは受領日時の新しい順。100 件ずつ表示する。
3. 履歴は証憑の詳細から開き、前後の値・理由・差し替え前の画像を見られる。

## 表示と印刷

1. **表示**: 証憑の詳細で、画像は画面に、PDF はブラウザの PDF の表示で出す。HEIC はブラウザで見られないので、表示用に JPEG へ変換する（原本は変換せずに保存したまま）。復号したファイルは、ブラウザに残らない設定（`Cache-Control: no-store`）で返す。
2. **取り出し**: 「原本を取り出す」で、保存した元のファイルをそのままダウンロードできる。ハッシュ（`shasum -a 256`）が詳細のハッシュと一致することを確かめられる。
3. **印刷**: 専用の印刷機能はない。表示した画像・PDF を、ブラウザの印刷、または取り出した原本を Mac のプレビューなどで開いて印刷する。画面の一覧・詳細は、ブラウザの印刷で紙または PDF にできる。
4. 見読性: 表示は、整然とした形で、すぐに出力できる状態にあることを、利用者が使う Mac のディスプレイとプリンターで確かめる。

## バックアップと復元

1. **対象**: 帳簿（暗号化した `.tbk` のバックアップファイル）と、証憑のファイル（`.tbk` の外の別のフォルダ）。
2. **バックアップ**: 画面の「今すぐバックアップ」、または 24 時間ごとの自動（解錠中だけ）。バックアップの置き場所の下 `trebuchet-receipts/<事業体>/` に、まだ写していない証憑のファイルだけを増分で写す。写したファイルは読み戻して検証する。名前は、ハッシュから鍵つきで作った別の名前にする（クラウドの同期フォルダに置いても、元のハッシュが見えない）。証憑の写しは世代の整理で消さない。写しに失敗したら、そのバックアップは失敗にする。
3. **復元**（server を止めて行う）:
   ```
   pnpm restore -- --file <.tbk のパス> [--data-dir <dir>] [--receipts-dir <dir>] [--yes]
   ```
   回復キーを標準入力から読む。`.tbk` と同じフォルダの `trebuchet-receipts/`（または `--receipts-dir`）から、各証憑のファイルを読み、復号と SHA-256 の検証をして、データ場所の `receipts/<事業体>/<ハッシュ>.trc` に戻す。1 件でも欠ける・壊れていれば、何も変えずに失敗する（`RECEIPTS_MISSING`）。帳簿だけを戻すときは `--allow-missing-receipts`（欠けた証憑は画面で「ファイルがありません」と出る）。
4. **復元前の退避**: 復元は今のデータを `.before-restore-<日時>/` に残す（証憑のファイルもその中の `receipts/`）。
5. **確認**: バックアップの置き場所の `trebuchet-receipts/` の件数が証憑の数と合うこと、復元の後に証憑を開いてハッシュが一致することを、【　　　　　　（頻度）】確かめる。
