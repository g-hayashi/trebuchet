# アプリ内マニュアル（012）

## 利用者の操作

全画面の右下に「マニュアル」を置く。施錠中・初回設定・ペアリング中も読める静的な内容で、帳簿のAPIは追加しない。パネルを閉じると元の入力とURLを保つ。本文・画像はアプリに同梱し、外部サイトや外部AIへ接続せず読める。

目的別の一覧と検索（目的・画面・ボタン・エラー・FAQの本文）、現在の画面に対応する記事、関連する手順、画像の別タブでの拡大を提供する。説明には開始画面・前提・操作と結果・注意事項・FAQを含める。画像の番号はキャプションに対応する。初回設定の回復キーやペアリングURLは撮影しない。

| 対象 | 配置 |
| --- | --- |
| 記事、画面との対応、根拠、画像とステップの対応 | `apps/web/src/features/manual/content.ts` |
| 検索・閲覧パネル | `apps/web/src/features/manual/ManualHelp.tsx` |
| 全画面での入口 | `apps/web/src/routes/__root.tsx`（AuthGateの外） |
| 同梱画像 | `apps/web/public/manual/` |
| 合成データでの撮影・代表操作・PC/スマホ確認 | `apps/web/e2e/manual.capture.ts`、`apps/web/manual.playwright.config.ts` |
| 変更検知・確認版 | `scripts/check-manual.ts`、`scripts/lib/manual-sources.ts`、`docs/manual-snapshot.json` |

## 更新手順

汎用の `$app-manual` を使う。記事の `paths` が画面との対応、`sources` が表示・処理の根拠。共通部品・共有スキーマと、関連するルート・ローカルのimport先もハッシュで追跡する。新規・削除画面、依存変更、記事や画像の欠落・差分は `pnpm manual:check` とCIで検出する。ハッシュは正しさを保証するものではなく、更新確認の漏れを検知するもの。

1. 変更対象の記事をコードと実際の操作で確認し、本文・FAQ・注意事項・画面対応を直す。
2. `pnpm manual:update` で撮影し、続けて確認版を更新する（`pnpm manual:capture` の後に `pnpm manual:record`。撮影が失敗すれば更新しない。別々にも実行できる）。既存のE2Eと同じポート（8787・5173）を使うため開発サーバーは停止する。既存サーバーには接続せず、毎回 `.tmp/e2e-*` の合成帳簿を作り、仮想パスキーで通常の認証を通す。撮影途中の画像は `.tmp/manual-capture/`、全撮影成功後の掲載画像は `apps/web/public/manual/` に置く。画像欠落・不正な画像・撮影失敗・撮影後の根拠変更がある場合は、確認版の更新を拒否する。
3. コミットの前に、本文と注釈番号を照合し、画像を実際に表示して読む（`git diff` で変わった画像を確かめる）。`manual-1280.png` と `manual-390.png` は `.tmp/manual-capture/` に出る閲覧パネルの検証画像。撮影時点の依存ハッシュと画像の成功記録も同じ場所に置く。秘密を含むtrace・動画は作らない。直すところがあれば、直して 2 からやり直す。
4. `pnpm manual:check` とプロジェクト必須の検証を実施し、記事・画像・確認版を同じコミットへ含める。

撮影・確認版の更新をCIから無条件に実行しない。本文の意味の確認を省略して確認版だけを更新しない。CIは更新漏れの検知までで、自動の文章生成・外部公開は行わない。再撮影はコマンドで自動化している。

## 対象と検証の境界

利用者向け全ルートを記事へ対応付ける。レイアウト専用の `__root.tsx` は入口の実装として追跡し、独立した記事にはしない。各フォームの補足・ダイアログは該当の目的の記事で扱う。記事自体はルートを増やさずパネル内で表示する。

掲載画像はローカルの実画面と合成データ。Tailscaleの状態取得だけは未導入の合成応答を使い、端末の接続情報を含めない。外部AI、Tailscaleの実接続、スマホ実機やOSのパスキー認証画面は撮影・成功検証の対象に含まない。接続や税務の適用可否を、ローカルの画面確認だけで保証しない。
