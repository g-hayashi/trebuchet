# Feature Specification: 帳簿コア（事業体・勘定科目・仕訳・帳票）

**Feature Branch**: `001-ledger-core`

**Created**: 2026-10-18

**Status**: Implemented

**Input**: User description: "フェーズ1の基盤のうち、帳簿の中心となる機能。事業体（テナント）を作成し、勘定科目などのマスタを整え、仕訳を手動で入力・訂正し、仕訳帳・総勘定元帳・試算表・PL・BSを表示できるようにする。要件の正本は docs/requirements.md の FR-01〜03, FR-09。"

## User Scenarios & Testing *(mandatory)*

### User Story 1 - 事業体を作成して帳簿を開始する (Priority: P1)

利用者は「個人事業」の事業体を作成する。作成時に、青色申告決算書に対応した勘定科目の初期セット、会計期間（1月1日〜12月31日）、消費税の設定（免税・税込経理）が用意される。続けて期首残高（現金、預金、売掛金、未払金、元入金など）を登録し、帳簿を開始できる。

**Why this priority**: すべての機能は事業体と勘定科目の上に成り立つ。これがないと何も記帳できない。

**Independent Test**: 新規の事業体を作成し、勘定科目の一覧と期首残高の試算表が表示されることで確認できる。

**Acceptance Scenarios**:

1. **Given** 事業体が1つもない, **When** 利用者が名前「個人事業」、種別「個人」、開始年度「2026年」で作成する, **Then** 青色申告決算書の各欄に対応づいた勘定科目の初期セットと、2026年1月1日〜12月31日の会計期間が作成される
2. **Given** 作成直後の事業体, **When** 利用者が期首残高を入力する, **Then** 借方合計と貸方合計が一致する場合のみ保存され、期首の貸借対照表に反映される
3. **Given** 事業体, **When** 利用者が補助科目（例：銀行口座1、クレジットカード3）と取引先を登録する, **Then** 仕訳の入力時に選択できる
4. **Given** 事業体, **When** 利用者が消費税の設定を「2027年1月1日から課税・税抜経理」のように期間を指定して追加する, **Then** 期間ごとの設定が履歴として残り、各仕訳の日付に応じて適用される設定が決まる

---

### User Story 2 - 仕訳を手動で入力する (Priority: P1)

利用者は、日付・借方科目・貸方科目・金額・摘要を入力して仕訳を登録する。1つの仕訳に複数行を持つ複合仕訳（例：入金時の源泉所得税の差し引き）も入力できる。貸借が一致しない仕訳は登録できない。

**Why this priority**: 帳簿の中心機能。これだけで記帳を始められる。

**Independent Test**: 単一行と複合の仕訳を登録し、仕訳帳に表示され、貸借不一致の仕訳が拒否されることで確認できる。

**Acceptance Scenarios**:

1. **Given** 事業体と勘定科目, **When** 利用者が「2026/10/31 売掛金 495,000 / 売上高 495,000 摘要: 10月分 取引先A」を登録する, **Then** 仕訳が登録され、仕訳番号が採番される
2. **Given** 事業体, **When** 利用者が借方2行・貸方1行の複合仕訳（普通預金 487,037 ＋ 事業主貸 7,963 / 売掛金 495,000。7,963 は差し引かれた源泉所得税）を登録する, **Then** 1つの仕訳として登録される
3. **Given** 事業体, **When** 借方合計と貸方合計が異なる仕訳を登録しようとする, **Then** 登録は拒否され、差額が表示される
4. **Given** 事業体, **When** 0円以下の金額、存在しない科目、会計期間外の日付、締め済みの年度の日付で登録しようとする, **Then** 登録は拒否され、理由が表示される
5. **Given** 仕訳の入力画面, **When** 利用者が科目・補助科目・取引先・税区分・メモタグを選ぶ, **Then** その仕訳行に記録される。税区分は日付に適用される消費税の設定から既定値が入る

---

### User Story 3 - 仕訳を訂正・取り消し、履歴と検索で確認する (Priority: P1)

利用者は、登録済みの仕訳の誤りを訂正・取り消しできる。訂正の内容と理由は履歴として残り、後から確認できる。仕訳は日付・金額・取引先の組み合わせで検索できる。

**Why this priority**: 誤りの修正は日常的に起きる。電子帳簿保存法の訂正削除履歴と検索要件を満たすために、最初から必要。

**Independent Test**: 仕訳を訂正・取り消しし、履歴に変更前の内容と理由が残り、検索で見つかることで確認できる。

**Acceptance Scenarios**:

1. **Given** 登録済みの仕訳, **When** 利用者が理由を入力して訂正する, **Then** 帳簿には訂正後の内容が反映され、変更前の内容・変更日時・理由が履歴に残る
2. **Given** 登録済みの仕訳, **When** 利用者が理由を入力して取り消す, **Then** 仕訳は帳簿の集計から除外されるが、データと履歴は残り、「取消済み」として参照できる
3. **Given** 理由が空欄, **When** 訂正・取り消しを実行する, **Then** 拒否される
4. **Given** 複数の仕訳, **When** 利用者が日付の範囲・金額の範囲・取引先を組み合わせて検索する, **Then** 条件に合う仕訳だけが表示される
5. **Given** 締め済みの年度の仕訳, **When** 訂正・取り消しを試みる, **Then** 拒否され、「当年度に訂正仕訳を起票する」操作が案内される
6. **Given** 締め済みの年度の仕訳に誤りがある, **When** 利用者が当年度の日付で訂正仕訳を起票する, **Then** 訂正仕訳は元の仕訳への参照つきで登録され、元の仕訳からも訂正仕訳をたどれる

---

### User Story 4 - 帳票を表示する (Priority: P2)

利用者は、期間を指定して仕訳帳、総勘定元帳（補助科目別を含む）、試算表、損益計算書、貸借対照表を表示する。損益計算書と貸借対照表は前年の同じ期間と比較できる。

**Why this priority**: 記帳した結果の確認と、決算・申告の基礎になる。記帳（US1〜3）ができてから価値が出るため P2。

**Independent Test**: 既知の仕訳を登録したうえで、各帳票の残高・合計が手計算の値と一致することで確認できる。

**Acceptance Scenarios**:

1. **Given** 期首残高と仕訳, **When** 利用者が総勘定元帳で「普通預金」を開く, **Then** 前期繰越から始まり、日付順に取引と残高の推移が表示される
2. **Given** 仕訳, **When** 利用者が試算表を表示する, **Then** すべての科目の借方合計と貸方合計が一致する
3. **Given** 仕訳, **When** 利用者が貸借対照表を表示する, **Then** 資産合計が負債・資本の合計（当期の利益を含む）と一致する
4. **Given** 前年と当年の仕訳, **When** 利用者が損益計算書を前年比較で表示する, **Then** 科目ごとに当年・前年・増減が表示される
5. **Given** 取り消した仕訳, **When** 帳票を表示する, **Then** 取り消した仕訳は集計に含まれない
6. **Given** 帳票, **When** 利用者がCSVでの出力を選ぶ, **Then** 表示内容と同じ数値のCSVが得られる

---

### User Story 5 - 年度を締める (Priority: P2)

利用者は、申告が終わった年度を「締め済み」にして、その年度の仕訳が変更されないようにする。必要な場合は、理由を記録したうえで締めを解除できる。

**Why this priority**: 申告後に帳簿が変わってしまう事故を防ぐ。ただし締めが必要になるのは年度末以降のため P2。

**Independent Test**: 年度を締めて、その年度の日付で仕訳の登録・訂正ができないことで確認できる。

**Acceptance Scenarios**:

1. **Given** 2026年度, **When** 利用者が年度を締める, **Then** 2026年の日付の仕訳は登録・訂正・取消ができなくなる
2. **Given** 締め済みの年度, **When** 利用者が理由を入力して締めを解除する, **Then** 再び変更できるようになり、解除の記録が残る

---

### User Story 6 - 2つ目の事業体に切り替える (Priority: P3)

利用者は、将来の法人などに備えて2つ目の事業体を作成し、画面上で切り替えて使う。事業体ごとのデータは互いに見えない。

**Why this priority**: 法人の設立は将来の予定であり、当面は個人事業だけで足りる。ただしデータを分離する設計は最初から必要。

**Independent Test**: 2つの事業体にそれぞれ仕訳を登録し、一方の帳票にもう一方の仕訳が現れないことで確認できる。

**Acceptance Scenarios**:

1. **Given** 事業体Aに仕訳がある, **When** 利用者が事業体Bを作成して切り替える, **Then** 事業体Bの帳票・検索には事業体Aの仕訳が一切表示されない
2. **Given** 事業体の種別「法人」, **When** 作成する, **Then** 作成できる。ただし法人向けの勘定科目の初期セットは本機能の範囲外で、個人用の初期セットを編集して使う

---

### Edge Cases

- 期首残高が未登録のまま仕訳を登録した場合：登録はできるが、貸借対照表に「期首残高が未登録」の警告を表示する
- 勘定科目の削除：仕訳で使われている科目は削除できず、「使用停止」にできる。使用停止の科目は新しい仕訳で選べないが、過去の帳票には表示される
- 科目名の変更：過去の仕訳を含めて新しい名前で表示される。変更の履歴は残る
- 会計期間をまたぐ日付：会計期間が存在しない日付の仕訳は拒否する。翌年度の会計期間は利用者が作成するか、翌年の日付の仕訳を最初に登録したときに作成を促す
- 金額の上限：1行あたり1兆円未満とする（入力ミスの検出）
- 同じ内容の仕訳を続けて登録：重複の可能性を警告するが、登録は妨げない（毎月の同額の家賃など、正当な反復があるため）
- 売掛金などの残高がマイナスになった場合：帳票で警告を表示する（過去の決算書で▲15,000円の売掛金が見つかった事例）
- 消費税の設定期間に空白や重複がある場合：設定を保存できない

## Requirements *(mandatory)*

### Functional Requirements

**事業体**

- **FR-001**: System MUST 利用者が事業体を作成・名称変更でき、種別（個人／法人）、会計期間の開始月を設定できる
- **FR-002**: System MUST 事業体ごとにデータを完全に分離し、ある事業体の操作・帳票・検索で別の事業体のデータを参照しない
- **FR-003**: System MUST 利用者が使う事業体を画面上で切り替えられる

**マスタ**

- **FR-004**: System MUST 個人事業の作成時に、青色申告決算書（一般用）の各欄に対応づいた勘定科目の初期セットを用意する。各科目は区分（資産・負債・純資産・収益・費用）、決算書の表示名と欄番号を持つ
- **FR-005**: Users MUST be able to 勘定科目を追加・名称変更・使用停止でき、使用中の科目は削除できない
- **FR-006**: Users MUST be able to 勘定科目ごとに補助科目（口座・カードなど）を登録できる
- **FR-007**: Users MUST be able to 取引先（名称、敬称、メモ）を登録・編集できる
- **FR-008**: Users MUST be able to メモタグを作り、仕訳行に複数付けられる
- **FR-009**: System MUST 消費税の設定（課税区分：免税／課税（本則・簡易・2割特例）、経理方式：税込／税抜）を事業体ごとに適用開始日つきで持ち、期間の空白・重複を許さない
- **FR-010**: System MUST 税区分（対象外、課税売上10%、課税売上8%（軽減）、課対仕入10%、課対仕入8%（軽減）、非課税、不課税など）の一覧を持つ

**期首残高・会計期間**

- **FR-011**: Users MUST be able to 会計期間ごとに期首残高を科目・補助科目別に登録でき、借方合計と貸方合計が一致する場合のみ保存できる
- **FR-012**: System MUST 会計期間（年度）を作成でき、各仕訳の日付はいずれかの会計期間に属する

**仕訳の入力**

- **FR-013**: Users MUST be able to 日付、1行以上の借方行と1行以上の貸方行（科目、補助科目、金額、税区分、取引先、摘要、メモタグ）、仕訳全体のメモを入力して仕訳を登録できる
- **FR-014**: System MUST 金額を1円単位の整数として扱い、端数を持たない
- **FR-015**: System MUST 借方合計と貸方合計が一致しない仕訳、金額が0以下の行、存在しないか使用停止の科目、会計期間外または締め済み年度の日付を含む仕訳を拒否し、理由を示す
- **FR-016**: System MUST 仕訳の登録時に、事業体内で一意かつ登録順に増える仕訳番号を採番する
- **FR-017**: System MUST 消費税の設定が税込経理の期間では、課税の税区分の行について税込金額から内税額を計算して記録する（1円未満切り捨て）。税率は仕訳の日付に適用される税率のデータから決める。免税期間の既定の税区分は「対象外」とする。税抜経理の期間の記帳は本機能の範囲外とし、その期間の日付の仕訳は理由を示して拒否する（設定の登録はできる）
- **FR-018**: System SHOULD 直前に登録した仕訳と同じ日付・科目・金額の仕訳を登録するとき、重複の可能性を警告する

**訂正・取消・履歴**

- **FR-019**: Users MUST be able to 締めていない年度の登録済みの仕訳を、理由を入力して訂正（書き換え）または取り消しできる。理由のない訂正・取消は拒否する
- **FR-019a**: Users MUST be able to 締め済みの年度の仕訳の誤りに対して、当年度の日付で訂正仕訳を起票でき、訂正仕訳は元の仕訳への参照を持つ。元の仕訳と訂正仕訳は相互にたどれる
- **FR-020**: System MUST 訂正・取消のたびに、変更前の仕訳の全内容、変更日時、理由を履歴として保存し、履歴は変更・削除できない
- **FR-021**: System MUST 取り消した仕訳を帳票の集計から除外しつつ、データとして保持し参照できるようにする
- **FR-022**: System MUST 仕訳を物理的に削除する操作を提供しない
- **FR-023**: Users MUST be able to 仕訳を日付の範囲、金額の範囲、取引先で検索でき、これらを組み合わせられる。科目・摘要・メモタグでも絞り込める

**年度の締め**

- **FR-024**: Users MUST be able to 年度を締め、理由を記録したうえで締めを解除できる。締め済み年度の日付の仕訳は登録・訂正・取消できない
- **FR-025**: System MUST 締めと解除の操作を日時・理由とともに記録する

**帳票**

- **FR-026**: System MUST 指定期間の仕訳帳（仕訳番号・日付順）を表示する
- **FR-027**: System MUST 指定期間の総勘定元帳を、科目別・補助科目別に、前期繰越・各取引・残高の推移とともに表示する
- **FR-028**: System MUST 指定期間の試算表（残高試算表）を表示し、借方と貸方の合計が一致することを示す
- **FR-029**: System MUST 指定期間の損益計算書と、指定日の貸借対照表を、青色申告決算書の科目順で表示する。当期の利益は貸借対照表の純資産に含めて表示する
- **FR-030**: System MUST 損益計算書と貸借対照表を、前年の同じ期間と比較して表示できる（当年・前年・増減）
- **FR-031**: System MUST すべての帳票を仕訳から都度導出し、集計値を独立して保存・編集させない
- **FR-032**: System MUST 帳票をCSVで出力でき、出力の数値は画面の表示と一致する
- **FR-033**: System MUST 資産・負債の科目の残高が通常と逆（例：売掛金がマイナス）になっている場合、帳票上で警告を表示する

### Key Entities

- **事業体**: 帳簿の単位。名称、種別（個人／法人）、会計期間の開始月。ほかのすべてのデータは事業体に属する
- **会計期間**: 事業体の年度。開始日、終了日、締めの状態
- **勘定科目**: 名称、区分、決算書の表示名と欄番号、表示順、使用停止の状態
- **補助科目**: 勘定科目の内訳（口座・カードなど）
- **取引先**: 名称、敬称、メモ
- **メモタグ**: 仕訳行に付ける自由なラベル
- **消費税の設定**: 適用開始日、課税区分、経理方式。事業体ごとの履歴
- **税区分**: 仕訳行に付ける消費税の分類
- **税率**: 税区分ごとの税率。適用開始日と出典を持つ
- **期首残高**: 会計期間ごと、科目・補助科目ごとの開始時点の残高
- **仕訳**: 仕訳番号、日付、メモ、状態（有効／取消済み）、訂正元の仕訳への参照（任意）、複数の仕訳行を持つ
- **仕訳行**: 借方／貸方、科目、補助科目、金額、税区分、税額、取引先、摘要、メモタグ
- **変更履歴**: 仕訳の訂正・取消、勘定科目の変更、年度の締め・解除の記録。対象、変更前の内容、日時、理由

## Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-001**: 利用者が事業体の作成から期首残高の登録までを10分以内に完了できる
- **SC-002**: 利用者が単一行の仕訳を30秒以内、3行の複合仕訳を1分以内に登録できる
- **SC-003**: 無作為に生成した1万件の仕訳を登録した状態で、試算表の借方合計と貸方合計が常に一致し、貸借対照表の貸借が常に一致する（不一致0件）
- **SC-004**: 年間2,000件の仕訳があるとき、各帳票が1秒以内に表示される
- **SC-005**: 訂正・取消したすべての仕訳について、変更前の内容と理由を100%さかのぼって確認できる
- **SC-006**: 日付・金額・取引先を組み合わせた検索で、条件に合う仕訳がもれなく、条件に合わない仕訳を含まずに表示される
- **SC-007**: 2つの事業体の間で、一方のデータがもう一方の画面・帳票・検索・CSVに現れる件数が0件である
- **SC-008**: 2025年分の青色申告決算書（R7）と同じ期首残高・仕訳を入力したとき、損益計算書と貸借対照表の各科目の金額が決算書の金額と一致する。実データの入力には freee の取込が必要なため、この基準は 002（freee 取込）の完了時に検証する

## Assumptions

- 利用者は本人1人だけ。権限の区分や同時編集は考えない（ログイン・認証は 004 で扱う）
- 会計期間の既定は1月1日〜12月31日（個人事業）。法人の任意の決算月は、開始月の設定で対応する
