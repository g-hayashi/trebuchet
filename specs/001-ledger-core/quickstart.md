# Quickstart: 001-ledger-core の動作確認

実装の完了後に、この手順で機能が動くことを確認する。詳細な仕様は [spec.md](./spec.md)、API は [contracts/http-api.md](./contracts/http-api.md) を参照。

## 前提

- macOS（Apple Silicon）、Node.js 26.5.1 以降、pnpm
- better-sqlite3 のビルド済みバイナリがない場合は Xcode Command Line Tools（`xcode-select --install`）

## セットアップ

```bash
pnpm install
pnpm typecheck && pnpm lint && pnpm test   # すべて成功すること
```

## 2. 手動での確認

実データ（`data/`）を汚さないよう、使い捨てのデータディレクトリで起動する（`pnpm dev` ではサーバーの作業ディレクトリが `apps/server` になるため、絶対パスで指定する）。

```bash
TREBUCHET_DATA_DIR="$PWD/.tmp/quickstart" pnpm dev   # server: http://127.0.0.1:8787 、web: http://localhost:5173
```

事業体を開くと表示されるメニュー（ホーム・仕訳・勘定科目・取引先・タグ・消費税・会計期間・帳票）から操作する。

1. **事業体の作成（US1）**: 最初の画面の「事業体を作成」で、名称「個人事業」・種別「個人」・開始年度「2026」で「作成する」→ 事業体のホームに移る。「勘定科目」の一覧に「売上高」「地代家賃」などが決算書の順で並ぶ（資産の末尾に事業主貸、純資産に事業主借・元入金）
2. **期首残高（US1）**: 「会計期間」→ 2026年度の「期首残高」で、「行を追加」して 普通預金（借方）1,000,000 / 元入金（貸方）1,000,000 を入力し「保存する」→「保存しました。」と表示され、「帳票」→「貸借対照表」に反映される。貸借が合わない間は差額が表示され、「保存する」が押せない（「差額が 0 円になると保存できます。」）
3. **仕訳（US2）**: 先に「取引先」で「取引先A」を追加しておく。「仕訳」→「仕訳を入力」で `2026-10-31 売掛金 495,000 / 売上高 495,000` を、売掛金の行の取引先を「取引先A」にして「登録する」→「仕訳 No.1 を登録しました。」と表示される。続けて「行を追加」で3行にし、各行の貸借を選んで複合仕訳 `普通預金 487,037 ＋ 事業主貸 7,963 / 売掛金 495,000`（7,963 は源泉所得税）を登録する（No.2）
4. **拒否（US2）**: 借方 500,000 / 貸方 495,000 → 差額 5,000 円が表示され、「登録する」が押せない（「差額が 0 円になると登録できます。」）
5. **訂正と履歴（US3）**: 「仕訳」の一覧から No.1 を開き、「訂正する」で両方の行の金額を 500,000 にして「訂正を保存」→「訂正の理由」の画面で理由を入れて「訂正を確定」→「変更履歴」に理由と変更前・変更後の行が表示される。理由が空（空白だけも同じ）の間は「訂正を確定」が押せない
6. **検索（US3）**: 「仕訳」の検索で 日付（から）2026-10-01・（まで）2026-10-31、金額（以上）400,000・（以下）500,000、取引先「取引先A」で「検索」→ No.1 だけが表示される（No.2 は取引先がないので出ない）
7. **帳票（US4）**: 「帳票」→「残高試算表」で「貸借一致」と表示され、合計の借方 = 貸方。「貸借対照表」で資産合計 = 負債・純資産合計。`2026-11-30 普通預金 10,000 / 売掛金 10,000` を登録して売掛金をマイナスにすると、試算表・貸借対照表に「売掛金の残高がマイナス（▲5,000）です」と警告が出る。「CSV をダウンロード」の数値が画面と一致する（CSV ではマイナスは `-5000` のような負の数）
8. **締め（US5）**: 「会計期間」→ 2026年度の「締める」→ 確認の画面で「締める」→ 状態が「締め済み」になる。2026年の日付で仕訳を登録すると「2026年度は締め済みです。訂正は訂正仕訳で行ってください」と表示されて登録されない。No.1 を開くと「訂正する」「取り消す」がなく、締め済みの案内と「当年度に訂正仕訳を起票」のリンクが表示される
9. **事業体の切替（US6）**: ヘッダーの「Trebuchet」から最初の画面に戻って2つ目の事業体を作成し、ヘッダーの「事業体」で切り替える（切り替えるとその事業体のホームに移る）→ 2つ目の事業体では、1つ目の仕訳が「仕訳」の一覧・検索、帳票（試算表・仕訳帳・貸借対照表）に出ない。データディレクトリ（上の例では `.tmp/quickstart/`、既定は `data/`）の `tenants/` に事業体ごとの `<事業体ID>.sqlite` が2つある（`-wal`・`-shm` は SQLite の作業ファイル）

確認が終わったら `pnpm dev` を止め、`.tmp/quickstart/` を削除する。

## 3. 実データでの照合（ローカル専用, 002 で実施）

SC-008（R7 の決算書との一致）は、freee の取込（002）を実装した後に、`work/` の実データを読むローカル専用のスクリプトで確認する。結果はリポジトリに含めない。

SC-008 は 2026-10-19 に、002 の T071（`scripts/verify-freee-import.ts` を 2025年分の実データで実行）で確認した。照合はすべての科目で一致し、PL・BS の科目別の金額は R7 の決算書と一致した。2026年分（途中経過）では FR-020a の警告は出なかった。
