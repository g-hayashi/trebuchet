# Quickstart: 001-ledger-core の動作確認

実装の完了後に、この手順で機能が動くことを確認する。詳細な仕様は [spec.md](./spec.md)、API は [contracts/http-api.md](./contracts/http-api.md) を参照。

## 前提

- macOS（Apple Silicon）、Node.js 26.5.1 以降、pnpm
- better-sqlite3 のビルド済みバイナリがない場合は Xcode Command Line Tools（`xcode-select --install`）

## セットアップ

```bash
pnpm install
pnpm typecheck && pnpm lint && pnpm test   # すべて成功すること
```

## 1. 自動テストでの確認

| コマンド | 確認する内容 | 対応 |
|---|---|---|
| `pnpm --filter @trebuchet/domain test` | 不変条件 INV-1〜10 のプロパティテスト（1万件の仕訳で貸借・BS が一致） | SC-003 |
| `pnpm --filter @trebuchet/db test` | 物理削除と監査ログの変更がトリガーで拒否される。テナント間でデータが見えない | FR-022, INV-9, SC-007 |
| `pnpm --filter @trebuchet/server test` | エラーコード（UNBALANCED, PERIOD_CLOSED など）と警告 | contracts/http-api.md |
| `pnpm --filter @trebuchet/web e2e` | 事業体の作成 → 仕訳 → 試算表の流れ | US1, US2, US4 |
| `pnpm bench:reports` | 2,000仕訳で各帳票が1秒以内 | SC-004 |

## 2. 手動での確認

```bash
pnpm dev     # server: http://127.0.0.1:8787 、web: http://127.0.0.1:5173
```

1. **事業体の作成（US1）**: 「個人事業」「個人」「2026年」で作成 → 勘定科目の一覧に「売上高」「地代家賃」などが決算書の順で並ぶ
2. **期首残高（US1）**: 普通預金 1,000,000 / 元入金 1,000,000 を登録 → 貸借対照表に反映。貸借が合わない入力は保存できない
3. **仕訳（US2）**: `2026-10-31 売掛金 495,000 / 売上高 495,000` → 仕訳番号が採番される。続けて複合仕訳 `普通預金 487,037 ＋ 事業主貸 7,963 / 売掛金 495,000`（7,963 は源泉所得税）を登録
4. **拒否（US2）**: 借方 500,000 / 貸方 495,000 → 差額 5,000 が表示され、登録されない
5. **訂正と履歴（US3）**: 手順3の仕訳の金額を理由つきで訂正 → 履歴に変更前の金額と理由が表示される。理由が空なら拒否
6. **検索（US3）**: 日付 10月、金額 400,000〜500,000、取引先A で検索 → 該当の仕訳だけが表示される
7. **帳票（US4）**: 試算表の借方合計 = 貸方合計。BS の資産合計 = 負債・純資産の合計。売掛金をマイナスにすると警告が出る。CSV の数値が画面と一致する
8. **締め（US5）**: 2026年度を締める → 2026年の日付で登録・訂正ができず、訂正仕訳の起票が案内される
9. **事業体の切替（US6）**: 2つ目の事業体を作成して切り替える → 1つ目の仕訳が帳票・検索に出ない。`data/tenants/` に DB ファイルが2つある
