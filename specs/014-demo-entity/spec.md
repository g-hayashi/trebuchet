# Feature Specification: デモ事業の作成

**Feature Branch**: `014-demo-entity`

**Created**: 2026-11-08

**Status**: Draft

**Input**: User description: "デモ事業の作成"（docs/requirements.md の FR-15。事業体の一覧が空のとき「デモ事業を作って試す」ボタンを出し、押したときだけ機能が一通り試せる架空の事業体を作る。自動では入れない〔2026-11-08 利用者の判断〕。開発用に作った `pnpm demo:seed`〔未コミット〕は参考にして作り直す。画面からの復元は 015 で別に扱う）

## User Scenarios & Testing *(mandatory)*

### User Story 1 - 初回起動でデモ事業を作って試す (Priority: P1)

初めてアプリを開いた利用者は、事業体が一つもない一覧の画面を見る。そこに「新しく事業体を作る」フォームと並んで「デモ事業を作って試す」ボタンがある。押すと、架空のデータが入った事業体が 1 つ作られ、そのホームが開く。利用者は自分の帳簿を始める前に、仕訳・帳票・請求・資産・証憑・明細の画面を実際のデータで触って、アプリで何ができるかを知る。

**Why this priority**: 空の帳簿では、どの画面に何が出るのかが分からず、最初の一歩が重い。ボタン 1 つで試せる状態になることが、この機能の価値そのもの。

**Independent Test**: 事業体のない新しいデータ場所でアプリを開き、ボタンを押す。デモ事業のホームが開き、仕訳の一覧・試算表・請求書・固定資産・証憑・明細の各画面にデータが出ること、試算表の借方と貸方の合計が一致することを確かめる。

**Acceptance Scenarios**:

1. **Given** 事業体が一つもない（アーカイブ済みのものだけがある場合も含む）, **When** 利用者が事業体の一覧を開く, **Then** 「デモ事業を作って試す」ボタンと、架空のデータで試すための事業体であることの短い説明が表示される
2. **Given** 事業体が一つもない, **When** 利用者がボタンを押す, **Then** デモ事業が 1 つ作られ、そのホームが開く。作成中は進行中であることが分かり、二重に押しても 1 つしか作られない
3. **Given** 作られたデモ事業, **When** 利用者が各画面を開く, **Then** 次のデータが見られる: 期首残高、補助科目（口座）、取引先（うち 1 件は源泉徴収の対象）、1 年分に分散した仕訳（訂正と取消を各 1 件含む）、家事按分の設定、固定資産（定額法・少額の特例・一括償却資産を各 1 件）と開業費、毎月の定期仕訳と計上済みの分、請求書（源泉徴収ありで入金済みのもの、未入金のもの）、仕訳に紐づいた証憑、未処理の明細
4. **Given** 作られたデモ事業, **When** 利用者が決算整理・締め・明細の承認・請求書の発行などの操作をする, **Then** 通常の事業体と同じルールで動く（デモだけの特別な扱いはない）
5. **Given** 事業体が 1 つ以上ある（アーカイブ済みでないもの）, **When** 利用者が一覧を開く, **Then** ボタンは表示されない

---

### User Story 2 - デモ事業だと分かり、試し終わったら消せる (Priority: P1)

デモ事業の各画面には、架空のデータであることを示す目印が常に出る。目印からは、試し終わったときの消し方（アーカイブして完全に削除）へ進める。利用者は本物の帳簿とデモを取り違えず、不要になればデモを跡形なく消せる。

**Why this priority**: 架空の仕訳や請求書が本物の帳簿と混同されると、申告や請求を誤るおそれがある（憲法 I）。作れることと同じくらい、区別でき消せることが必要。

**Independent Test**: デモ事業の任意の画面で目印が出ていること、通常の事業体では出ないことを確かめる。目印の案内に沿ってアーカイブし、完全に削除すると、一覧からも消え、再びボタンが表示されることを確かめる。

**Acceptance Scenarios**:

1. **Given** デモ事業, **When** 利用者がホーム・仕訳・帳票・請求書・決算書などどの画面を開いても, **Then** 「デモ用の架空のデータです」という目印が表示される。事業体の名前にも「デモ」が含まれる
2. **Given** 通常の事業体, **When** 利用者が画面を開く, **Then** 目印は表示されない
3. **Given** デモ事業の目印, **When** 利用者が「試し終わったら削除」の案内を開く, **Then** 既存のアーカイブと完全な削除の手順へ進める（削除には既存と同じ名前の確認が要る）
4. **Given** デモ事業を完全に削除し、他に事業体がない, **When** 一覧を開く, **Then** ボタンが再び表示され、もう一度デモ事業を作れる
5. **Given** デモ事業の請求書, **When** 利用者が印刷用の画面を開く, **Then** 架空のデータであることが印刷物にも分かる（実在の取引先へ誤って送らないため）

### User Story 3 - 起動した時期に合ったデータで試す (Priority: P2)

デモのデータの日付は、利用者がボタンを押した日に合わせて作られる。どの時期に試しても、未来の日付の仕訳はなく、今年（または直近の年）の帳簿として自然に見える。

**Why this priority**: 固定の年のデータでは、翌年以降に試すと古い年の帳簿になり、ホームの「今月」や期日の表示が空になる。ただし US1・US2 があれば価値は出るため P2。

**Independent Test**: 日付を変えた時計で作成し、全仕訳の日付が作成日以前で、会計年度が作成日に合っていることを確かめる。

**Acceptance Scenarios**:

1. **Given** 作成日が 3 月以降, **When** デモ事業を作る, **Then** 会計年度は作成日の年で、仕訳・請求・資産・証憑・明細の日付はすべてその年の 1 月 1 日から作成日までに収まる
2. **Given** 作成日が 1 月か 2 月, **When** デモ事業を作る, **Then** 1 年分のデータが入るよう会計年度は前の年になり、日付はすべて前の年に収まる
3. **Given** どの作成日でも, **When** デモ事業を作る, **Then** 作成日より後の日付の仕訳・請求書・入金・証憑・明細はない

---

### Edge Cases

- **作成の途中で失敗した**: デモ事業は全部作られるか、何も残らない。中途半端な事業体が一覧に残らず、利用者はもう一度ボタンを押せる
- **施錠中・未認証**: 通常の事業体の作成と同じく、解錠して認証されているときだけ作れる
- **デモ事業がアーカイブ済みで残っている**: 事業体が一つもない扱いなのでボタンは出る。作ると名前が重ならないよう区別できる名前になる
- **AI の設定が有効**: デモの作成では、端末内・外部のどちらの AI も呼ばない。明細は承認していない状態で残し、利用者が承認するときに初めて通常の経路で候補が出る
- **バックアップ**: デモ事業も通常の事業体と同じくバックアップと復元の対象になる（目印も引き継ぐ）
- **リモート（スマホ）から開いた**: 通常の事業体の作成と同じく、作成を許す権限のときだけボタンが使える

## Requirements *(mandatory)*

### Functional Requirements

- **FR-001**: アーカイブ済みでない事業体が一つもないとき、事業体の一覧に「デモ事業を作って試す」ボタンと短い説明を表示しなければならない。事業体があるときは表示してはならない
- **FR-002**: 利用者がボタンを押したときだけデモ事業を作らなければならない。初回の設定・起動・その他の操作で自動的に作ってはならない
- **FR-003**: デモ事業は、US1 の受け入れシナリオ 3 のデータ（期首残高、補助科目、取引先と源泉徴収の対象、訂正・取消を含む仕訳、家事按分、固定資産 3 種と開業費、定期仕訳と計上分、入金済み・未入金の請求書、仕訳に紐づいた証憑、未処理の明細）をすべて含まなければならない
- **FR-004**: デモのデータは、通常の操作で作るのと同じ業務ルール・監査の記録を通って作られなければならない。帳簿の不変条件（借方と貸方の一致など）を満たさなければならない
- **FR-005**: デモ事業の作成は全部か無かでなければならない。途中で失敗したときは事業体も証憑のファイルも残してはならない
- **FR-006**: デモの取引先名・摘要・金額・画像・明細はすべて架空で、製品に同梱した合成の素材から作らなければならない。実データ・テスト用の素材を読んではならない
- **FR-007**: デモ事業の作成では、端末内・外部のいずれの AI も呼んではならず、外部へ何も送ってはならない
- **FR-008**: デモ事業であることを記録し、そのすべての画面（印刷用の請求書を含む）に架空のデータである目印を表示しなければならない。事業体の名前には「デモ」を含めなければならない
- **FR-009**: 目印から、既存のアーカイブと完全な削除の手順へ進めなければならない。削除の確認は既存の事業体と同じでなければならない
- **FR-010**: デモのデータの日付は作成日に合わせて決めなければならない（US3）。作成日より後の日付を作ってはならない
- **FR-011**: 決算整理の登録と年度の締めはデモの作成で行ってはならない（利用者が試す操作として残す）。明細は未処理のまま残さなければならない
- **FR-012**: デモ事業の作成は、通常の事業体の作成と同じ認証・権限・施錠の検査を通らなければならない
- **FR-013**: 二重に押しても、同時に作られるデモ事業は 1 つでなければならない
- **FR-014**: アプリ内マニュアルに、デモ事業の作り方・目印・消し方を説明する記事（または既存記事の節）を加えなければならない

### Key Entities

- **デモ事業**: 通常の事業体に「デモである」という印が付いたもの。名前に「デモ」を含む。会計年度は作成日から決まる。削除は通常の事業体と同じ
- **デモの素材**: 製品に同梱した架空のデータの定義（取引先、仕訳の明細、資産、請求の工数、証憑の画像、明細のファイル）。日付は作成日からの相対で決まる

## Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-001**: 事業体のない状態から、ボタンを押してデモ事業のホームが開くまで 10 秒以内
- **SC-002**: デモ事業の作成後、US1 の受け入れシナリオ 3 に挙げた 11 種のデータがそれぞれ 1 件以上あり、試算表の借方と貸方が一致する（100%）
- **SC-003**: どの作成日（年内の全日付）で作っても、作成日より後の日付のデータは 0 件
- **SC-004**: デモ事業のすべての画面で目印が表示され、通常の事業体では 0 画面
- **SC-005**: デモ事業を完全に削除した後、そのデモの事業体・証憑のファイルは残らない（0 件）
- **SC-006**: 作成の途中で失敗させたとき、一覧に残る事業体は 0 件

## Assumptions

- 対象は個人事業・1 月始まりの事業体（001 の作成の制約と同じ）。消費税は免税・税込（作成時の既定）
- 「デモ」の名前は既定で「デモ事業（サンプル）」。重なるときは区別できる名前にする。名前の変更は通常の事業体と同じくできる（目印は消えない）
- 会計年度は 1 つだけ作る。2 年度以上・期首残高の繰越の体験は対象外
- データの量と内容は、開発用に作った `pnpm demo:seed`（取引先 3、仕訳 40 程度、資産 3、開業費 1、請求書 2、定期仕訳 1、証憑 3、明細 10）を目安にする。作成日が年の早い時期でも 1 年分を見せるため、1〜2 月は前の年にする
- ボタンは事業体の一覧の空の状態だけに置く。事業体があるときに追加でデモを作る入口は設けない（必要になれば後で足す）
- 開発用の `pnpm demo:seed` と関連の未コミットの変更（`scripts/seed-demo.ts`、`scripts/lib/demo-seed.ts`、`scripts/lib/terminal.ts`、`apps/server/test/demo-seed.test.ts`、`package.json`・`AGENTS.md`・`scripts/restore-backup.ts` の差分）は、この機能の実装の参考にした後、取り込まずに消す
- マニュアル撮影（012）のデータの用意をデモ事業に置き換えることは対象外
