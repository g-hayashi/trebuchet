# 不変条件の索引（INV-1〜60）

不変条件の番号は機能をまたいで通し番号。**正本は各機能の `data-model.md` §4**（検証の手段もそこにある。008 は `data-model.md` がなく、[design.md D10](008-passkey-vault/design.md)）。この表は索引で、説明は一行に要約している。食い違いがあれば `data-model.md` が正しい。テストは fast-check の性質テストか統合テスト（[AGENTS.md](../AGENTS.md)「開発の進め方」）。

## 001 帳簿コア（INV-1〜10）— [data-model §4](001-ledger-core/data-model.md)

| INV | 内容 |
|---|---|
| INV-1 | 有効な仕訳ごとに Σ借方 = Σ貸方 |
| INV-2 | 各仕訳は借方行・貸方行を 1 行以上ずつ持つ |
| INV-3 | 金額は 0 < amount < 10^12 の整数 |
| INV-4 | 試算表の借方合計 = 貸方合計 |
| INV-5 | 資産 = 負債 + 純資産 + 当期利益 |
| INV-6 | 取消済みの仕訳は集計に影響しない |
| INV-7 | 締め済み年度の仕訳は変更されない |
| INV-8 | 仕訳番号は単調増加で重複しない |
| INV-9 | audit_log は追記のみ |
| INV-10 | 内税額 = floor(税込額 × 税率 / (100 + 税率))。税率は仕訳の日付で決まる |

## 005 請求と定期仕訳（INV-30〜39）— [data-model §4](005-recurring-invoicing/data-model.md)

| INV | 内容 |
|---|---|
| INV-30 | 請求書の total = Σ明細 = 売上の仕訳の金額。税額は税率ごとの内税の式に従う |
| INV-31 | 事業体の中で seq・請求番号は重複せず、発行の順に増え、取消した番号は再使用されない |
| INV-32 | 発行・消し込み・取消は全部か無か（請求書 ⇔ 仕訳の対応が保たれる） |
| INV-33 | 消し込みの充当額の合計 ≤ total。状態は残額だけで決まる |
| INV-34 | 取引先ごとの請求・入金に結びつく仕訳の売掛金残高 = 取消でない請求書の残額の合計 |
| INV-35 | 定期仕訳は（定義, 月）ごとに高々 1 件登録され、判定の漏れがない |
| INV-36 | `clampDay` と `dueDate` は常にその月の範囲に収まる |
| INV-37 | 明細の金額と別記の税額の計算は整数で、小計 + 税額 = 税込の合計 |
| INV-38 | 発行済みの請求書の写しは、設定・取引先・条件・工数のどんな変更の後も変わらない |
| INV-39 | `source` が `invoice`・`payment` の仕訳は、請求・入金の取消以外では訂正・取消されない |

## 006 明細の取込と AI 仕訳（INV-40〜47）— [data-model §5](006-mfme-ai-journal/data-model.md)

| INV | 内容 |
|---|---|
| INV-40 | 事業体の中で `stable_key` は重複せず、同じ入力を何回取り込んでも 2 回目以降に加わる明細は 0 件（行の順に依らない） |
| INV-41 | 取込・候補の作成・除外・ルールの変更のどんな列の後も、仕訳帳と試算表は変わらない（承認だけが仕訳を作る） |
| INV-42 | `created` の結びつきの仕訳は R5 の表どおりの形で、明細の口座の行の金額 = \|明細の金額\|、向きは入金なら借方・出金なら貸方。貸借は一致する |
| INV-43 | 有効な結びつきは、明細ごとに高々 1 件、仕訳の行ごとに高々 1 件 |
| INV-44 | 明細の状態は結びつき・除外・仕訳の状態だけで決まる。仕訳の取消で未処理に戻り、訂正では登録済みのまま |
| INV-45 | AI への送信の内容（`buildAiPayload`）のマスクした項目に 4 桁以上の数字と振込の名義がなく、どこにも口座の名前・メモがない |
| INV-46 | AI の出力から作る候補は `AiSuggestion` の検証を通り、科目・税区分が有効なものだけ。それ以外は `none` |
| INV-47 | 取込と承認は全部か無か。明細が `registered` ⇔ 有効な結びつきの仕訳がある |

## 008 パスキーと回復キーによる DB の暗号化（INV-51〜54）— [design.md D10](008-passkey-vault/design.md)

| INV | 内容 |
|---|---|
| INV-51 | DK・DB の鍵・バックアップの鍵は、平文でディスク・ログ・環境変数・応答に出ない（回復キーは作成・再発行の応答で 1 回だけ）。施錠中に registry・事業体の DB を開く経路はない（`VaultLockedError`） |
| INV-52 | どの包み（パスキー・回復キー）を開いても同じ DK になる。AAD（種類・資格情報 ID）を替えた包み、誤った ikm では開けない |
| INV-53 | 設定済みなら、回復キーの包みは常に 1 行、パスキーの包みはパスキーと 1 対 1 で、パスキーは 1 本以上 |
| INV-54 | バックアップは、そのときの回復キーでも、取った時点の回復キーでも復号できる。誤った鍵では本体を 1 バイトも使わずに失敗する |

## 009 定額法・一括償却資産・開業費の償却（INV-55〜60）— [data-model §4](009-depreciation-deferred/data-model.md)

| INV | 内容 |
|---|---|
| INV-55 | 定額法: 各年度 0 ≤ 償却費 ≤ 期首の未償却残高 − 1、月数は 1〜12、期末 = 翌年度の期首。除却しなければ償却費の合計 = 取得価額 − 前年までの累計 − 1、除却（廃棄・売却）すれば除却の年度の期末は 0 |
| INV-56 | 一括償却: 各年度の額は 0 以上の整数で、n 年度の合計 = 取得価額 − 前年までの累計、以後は 0。除却で額は変わらず、除却損は常に 0 |
| INV-57 | 償却の案は INV-23 を満たし、資産の勘定の貸方 = 償却費 + 除却の年度の残高（廃棄は除却損、売却は事業主貸へ）、減価償却費・除却損の純額 = 必要経費算入額、算入額 + 家事分 = 償却費 |
| INV-58 | 開業費: 0 ≤ 決定の額 ≤ 期首の未償却残高、未償却残高は負にならず、0 ≤ 目安 ≤ 未償却残高。0 円は案を作らず、有効な仕訳のない決定は翌年度の上限を減らさない |
| INV-59 | 案をすべて登録して繰り越した帳簿では、どの年度も帳簿と台帳の期首の照合（`ASSET_REGISTER_MISMATCH`）と欄 18 の照合（`DEPRECIATION_MISMATCH`）の警告が出ない |
| INV-60 | どの（資産・開業費, 年度）でも有効な償却の仕訳は高々 1 件。登録済みなら案は出ず、確定は `ADJUSTMENT_NOT_NEEDED`。取り消すと案が再び出る |
