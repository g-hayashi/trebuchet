## 2. 手動での確認（合成のデータ）

```bash
TREBUCHET_DATA_DIR="$PWD/.tmp/quickstart-003" pnpm dev   # http://127.0.0.1:5173
```

「決算書」の画面は `/e/<事業体>/blue-return/<年>`、控除の回答は `…/blue-return/<年>/deduction`、按分は `…/blue-return/<年>/home-use`、固定資産台帳は `/e/<事業体>/fixed-assets?year=<年>`、控えは `/e/<事業体>/tax-return/<年>`。金額は 002 のフィクスチャ（`journal-2025.csv`）を取り込んだ直後の値で、手順を進めると変わる箇所は注記した。

1. **準備**: 事業体を名称「決算書テスト」・種別「個人」・開始年度「2024」で作成する。「会計期間」→「翌年度を作成」で 2025年度を作る。「取込」→「新しい取込」→「仕訳帳のファイル」に `packages/domain/test/fixtures/freee/journal-2025.csv` を選び、「対応表を保存」→「取り込む」→「14件の仕訳を取り込みました。」。このフィクスチャに地代家賃はないので、按分は通信費で確かめる（手順4）
2. **損益計算書（US1）**: 「決算書」→「2025年分」を開く → 「締め前（暫定）」と「2025年分の様式」が出る。1ページの欄1 が 450,000、欄12（通信費）4,400、欄14（接待交際費）14,260、欄17（消耗品費）9,900、欄18（減価償却費）60,000、欄25（支払手数料）31,290、欄32（計）119,850、欄33・欄43 が 330,150。控除の回答前は、「第一表に転記する値」の欄44・欄45 が「要件の回答が必要」で、警告に「青色申告特別控除の要件の回答が未登録です。控除額と所得金額は計算していません」が出る。期首残高を入れる前は、警告に「工具器具備品の残高がマイナス（▲60,000）です」「未払金の残高がマイナス（▲2,940）です」と、「3ページの必要経費算入額の合計（0 円）が欄18 の減価償却費（60000 円）と一致しません」も出る（前の2つは手順6、3ページとの不一致は手順5 で解消する）
3. **控除（US1）**: 「要件を回答する」で「青色申告特別控除の要件（2025年分）」を開き、5項目（複式簿記、貸借対照表と損益計算書の添付、期限内の申告、e-Tax、優良な電子帳簿）をすべてチェックして「保存」→ 「上限額: 650,000 円」。決算書の「青色申告特別控除の計算」は区分「最大」・上限額 650,000・控除額 330,150（控除前の所得金額が上限より小さいので、控除額は所得金額まで）、欄44 が 330,150、欄45 が 0。「e-Tax で申告データを送信する」と「優良な電子帳簿の保存の要件を満たしている」を外して「保存」→「上限額: 550,000 円」と、満たしていない要件「e-Tax での送信または優良な電子帳簿の保存」が出る。欄44・欄45 は決算書の最上部の「確定申告書 第一表（事業所得）に転記する値」に出る
4. **家事按分（US2）**: 「家事按分・地代家賃の内訳」で科目「通信費」・事業専用割合「50」で根拠を空のまま「保存」→ 「按分の根拠を入力してください」（保存されない）。根拠「通信回線の利用時間の半分」を入れて「保存」→ 「按分の登録」の表に「通信費 50%」が出て、「決算整理の仕訳の案」に帳簿の金額 4,400・事業分 2,200・家事分 2,200、日付 2025-12-31、摘要「家事按分の振替（通信費 事業専用割合 50%）」、借方 事業主貸 2,200／貸方 通信費 2,200 が出る → 「仕訳を登録」→ 案は「登録する仕訳の案はありません。」になり、決算書の欄12 が 2,200、貸借対照表の事業主貸（期末）が 50,000 から 52,200 に増える。仕訳（2025-12-20、借方 通信費／貸方 現金 1,000 円）を1件足す → 決算書の警告に「家事按分の振替（通信費）が帳簿と合っていません。家事分 2700 円に対して振替済みは 2200 円です（差額 500 円）」と「仕訳の案を見る」のリンクが出て、按分の画面の案は帳簿の金額 5,400・家事分 2,700、借方 事業主貸 500／貸方 通信費 500 になる → 「仕訳を登録」で警告が消える（欄12 は 2,700）
5. **少額減価償却資産（US3）**: 「固定資産台帳」（`?year=2025`）で、資産名「高額PC」・数量 1・取得年月日 2025-09-01・取得価額 300000・資産の勘定「工具器具備品」で「登録」→ 「取得価額が基準額（300000 円）以上のため、少額減価償却資産の特例は使えません」（登録されない）。資産名「ノートPC」・取得価額 150000 に直して「登録」→ 台帳に本年分の償却費・必要経費算入額 150,000、未償却残高 0 で出て、「決算整理の仕訳の案」に「減価償却費の計上（ノートPC 少額減価償却資産 事業専用割合 100%）」、借方 減価償却費 150,000／貸方 工具器具備品 150,000 が出る → 「仕訳を登録」。フィクスチャには 12/31 付の減価償却費 60,000 の仕訳（仕訳 No.14）が入っているので、資産名「備品A」・取得年月日 2025-12-31・取得価額 60000・結びつける仕訳「2025-12-31 #14」で「登録」する（結びつけた資産は仕訳の案が出ない）→ 決算書の3ページの必要経費算入額の合計 210,000 が欄18（210,000）と一致し、「一致しません」の警告が消える
6. **貸借対照表（US4）**: 「会計期間」→ 2025年度の「期首残高」→「freee の元帳から読み込む」で「総勘定元帳のファイル」に `ledger-2025.csv` を選ぶ → 6行（借方・貸方とも 1,070,000 円）が入り、警告「「売掛金」の期首残高がマイナス（▲20,000円）のため、貸方の残高にしました」が出る → 「保存する」→「保存しました。」。決算書の4ページの期首は現金 30,000・その他の預金 800,000・売掛金 ▲20,000（貸方）・工具器具備品 240,000・未払金 15,000・元入金 1,035,000 になり、「工具器具備品の残高がマイナス」「未払金の残高がマイナス」の警告は消える（期末は工具器具備品 30,000・未払金 12,060）。この時点の 4ページの下は「元入金の繰越の検査: 前の年度なし」。次に、2024年度に次の仕訳を6件入れる（「仕訳」の「新しい仕訳」か、同じ内容を API で登録する）: 2024-06-30 借方 普通預金／貸方 売上高 100,000、2024-01-10 借方 工具器具備品／貸方 事業主借 240,000、同日 借方 現金／貸方 事業主借 30,000、同日 借方 普通預金／貸方 事業主借 700,000、2024-12-31 借方 事業主貸／貸方 売掛金 20,000、同日 借方 事業主貸／貸方 未払金（補助科目「ABCカード」）15,000 → 2025年分の決算書で「元入金の繰越の検査: 一致」（警告に「前の年度（2024年度）は締め前です。繰越の検査は締め前の帳簿で行っています」は出る）。2024年分の決算書には警告「売掛金の残高がマイナス（▲20,000）です」が出る。期首残高の売掛金を貸方 10,000、元入金を貸方 1,045,000 に直して保存する → 「元入金の繰越の検査: 食い違い」と、売掛金（▲20,000 と ▲10,000、差額 10,000）・元入金（1,035,000 と 1,045,000、差額 10,000）の表、警告「「売掛金」の期首残高（-10000 円）が、前の年度の期末から求めた値（-20000 円）と違います（差額 10000 円）」が出る → 説明の欄に文を入れて「説明を保存」→ 警告の下に「説明: …」が出る。未払金は前の年度でも補助科目を同じにしておく（補助科目の有無が違うと、「未払金」の行が2つ出て差額が別々に出る）
7. **月別売上と売上先（US5）**: 2ページの月別売上で 1月 330,000・6月 110,000・11月（売上 6,600・雑収入 3,400）、合計は売上 446,600・雑収入 3,400・計 450,000 で欄1（450,000）と一致する。3ページの売上先は「株式会社サンプル」440,000・「上記以外の売上先の計」10,000・合計 450,000。取引先なしの売上が「上記以外」に入り、「取引先が付いていない売上: 1 件、6,600 円」と警告「取引先が付いていない売上の行が 1 件（6600 円）あります。「上記以外の売上先の計」に含めています」で知らされる（上記以外の 10,000 は取引先なしの売上 6,600 と雑収入 3,400）
8. **控え（US6）**: 「申告の控え」（`/tax-return/2025`）の「控えの登録」で、控えの種類「社会保険料控除」・項目名「国民健康保険料」・金額 120000・ファイルの場所 `<リポジトリ>/.tmp/quickstart-003/receipt-sample.pdf`（作成しておく）で「控えを登録」→ 一覧の「ファイル」の欄が「あり」。もう1件、存在しないパス（例: `…/.tmp/quickstart-003/missing-file.pdf`）で登録 → 「見つかりません」（登録の後は「控えの種類」が先頭の「給与所得」に戻るので、2件目は種類を選び直す）
9. **免税の期間（US7）**: 新しい事業体（既定で免税）で、「取込」→「新しい取込」に `journal-2025.csv` を選ぶ（費用に課税の税区分が付いた 2025-04-15 の仕訳 5041501 を含む）→ プレビューの警告は「1件」で、「警告（取込は妨げません）」に「免税の期間のため税区分の警告を 1 件まとめました」（折りたたみ）、仕訳ごとの判定の 5041501 の行に「免税の期間のため税区分の警告をまとめた」が出る
10. **出力**: 「CSV をダウンロード」（`/api/entities/<事業体>/blue-return/2025/csv`、UTF-8、ファイル名 `blue-return-2025.csv`、1行目 `ページ,欄番号,欄名,金額`）の値が画面と一致する（欄1 450000、欄12 2700、欄18 210000、欄32 268150、欄33・欄43・欄44 181850、欄45 0）。「印刷」（ブラウザの印刷）では、操作のボタン・警告・入力欄が隠れ、1〜3ページの後で改ページされて A4 の4ページに分かれる（印刷の表示でのスタイルを確かめた。実際の用紙の出力は手元の印刷のプレビューで確かめる）

手順2〜5（決算書を開く → 控除の回答 → 按分 → 資産 → 転記の値を確かめる）は、ブラウザの自動操作で約3分だった（SC-005 は 30分以内）。

確認が終わったら `pnpm dev` を止め、`.tmp/quickstart-003/` を削除する。

## 3. 実データでの照合（ローカル専用）

SC-001・SC-002 を確かめる。出力と実データの数値はリポジトリに含めない（research R15）。

```bash
node scripts/verify-tax-return.ts \
  --journal work/<2025年分の仕訳帳>.csv --ledger work/<2025年分の総勘定元帳>.csv \
  --year 2025 --closing work/tax-return-2025.json [--mapping .tmp/<対応表>.json]
```

- `work/tax-return-2025.json`（利用者が手で作る。形はスクリプトの先頭のコメント）に、按分・資産・控除の回答と、R7 の決算書の欄の値を書く
- 1〜4ページの金額の欄が R7 とすべて一致する（SC-001）
- 2024年分を先に取り込み（`--keep`）、2025年分を `--continue` で足したとき、2024年末の負の売掛金と、2025年の期首と 2024年の期末の食い違い（売掛金・未払金・元入金）が警告に出る（SC-002）
