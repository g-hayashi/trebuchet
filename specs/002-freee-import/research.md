# Research: 002-freee-import

調査日: 2026-10-19。freee の書き出しファイルの事実は、セッションの分析メモ（`analysis-journal.md`、`analysis-tax-return.md`）による。
実データの金額・取引先はこのファイルに書かない（Constitution III）。例の金額は合成の値。

## 前提となる事実（分析メモより）

- 書き出しは2種類。**仕訳帳**（UTF-8、BOM なし、LF、全項目クォート、103列、日付 `YYYY/MM/DD`）と **総勘定元帳**（CP932、1行目がタイトル・2行目がヘッダ、24列、日付 `YYYY-MM-DD`）
- 仕訳帳は1行に借方と貸方の両方を持つ（片側が空の行もある）。複合仕訳は `仕訳ID` を共有し、`仕訳行番号`・`仕訳行数` で区別する。`No`・`レコード番号` はファイル内の連番で、`取引ID` は1対多のため鍵に使えない
- 口座（「その他口座」）とクレジットカード（各カード名）は **勘定科目** として表れ、補助科目名の列にも同じ名前が入る。部門・品目・取引先コードは未使用
- 税区分の表記は「対象外」「課税売上10%」「課対仕入10%」「課対仕入8%（軽）」（`%` は半角、括弧は全角）。税額はすべて内税・切り捨てで、001 の INV-10 と一致する
- 元帳は科目ごとのブロック。開始行は相手勘定科目が「開始残高」または「前期繰越」で、残高だけが入る。補助科目の列はなく、合計行・月計行はない（行数からの推測）
- **年初付の決算振替**: 前年分の決算として、期首日の日付で「事業主借→元入金」「損益→元入金」「元入金→事業主貸」の3行の仕訳が入る（`決算整理仕訳 = 1`、`登録した方法 = 決算`）。元帳の前期繰越はこの振替の **前** の値で、振替は当年の元帳の取引行として表れる
- 決算書（R7）の期首の貸借対照表は「前期繰越 ＋ 年初付の決算振替」と一致する（分析メモで検算済み）

## R1. ファイルの判別と文字コード

- **Decision**: バイト列を受け取り、BOM を除いて UTF-8 の厳密なデコード（`TextDecoder("utf-8", { fatal: true })`）を試し、失敗したら `TextDecoder("shift_jis")` でデコードする。デコード後、先頭5行の中から必須の列名をすべて含む行をヘッダとし、その列の組み合わせで「仕訳帳」「総勘定元帳」を判別する。どちらにも当たらなければ `IMPORT_UNKNOWN_FORMAT`
- **Rationale**: WHATWG の Shift_JIS デコーダーは Windows-31J（CP932）の拡張文字を含み、Node とブラウザの両方で標準の `TextDecoder` で扱える。行の分割はデコードの後に行う（CP932 の2バイト目 0x85 を改行と誤認しないため）。`TextDecoder` はグローバルにあるので、ドメイン層の制約（Hono・DB・node:fs を使わない）を守れる
- **Alternatives**: `iconv-lite`（依存が増える。標準で足りる）、利用者に文字コードを選ばせる（手間が増え、誤りの元になる）

## R2. CSV の解析

- **Decision**: RFC 4180 の解析器をドメイン層に自作する（引用、`""` のエスケープ、引用内の改行、CRLF/LF）。001 の `toCsv` と組み合わせた往復のプロパティテスト（`parse(toCsv(rows)) = rows`）で検証する
- **Rationale**: 必要な機能は小さく（数十行）、プロパティテストで十分に検証できる。Constitution VII（標準や既存で代替できるなら依存を足さない）
- **Alternatives**: `csv-parse`、`papaparse`（依存の追加に見合う機能差がない）

## R3. 列の特定

- **Decision**: 列は位置ではなく **ヘッダの列名** で特定する。取込に使う列名の一覧をドメイン層の定数に置き、必須の列が欠けていればそのファイルを拒否する。列名の完全な文字列は分析メモにないため、実装の最初にローカル専用の確認スクリプト（R18）で実ファイルのヘッダと照合する
- **使う列（仕訳帳）**: 取引日、仕訳ID、仕訳番号、仕訳行番号、仕訳行数、決算整理仕訳、登録した方法、取引内容、借方／貸方の 勘定科目・補助科目名・金額・税区分・税金額・取引先名・メモ（メモタグ）・備考
- **使う列（元帳）**: 勘定科目、取引日、決算整理仕訳、相手勘定科目、仕訳番号、借方金額、貸方金額、残高
- **Rationale**: freee が列を追加・並べ替えても壊れにくい。公式の列仕様は未照合のため、照合の手順を計画に入れる
- **Alternatives**: 列の位置で読む（freee の仕様変更で黙って誤る）
- **確認結果（T005、2025年分の実ファイル）**:
  - 仕訳帳: UTF-8、ヘッダは1行目、103列。上の列名は「登録方法」を除いてすべて一致した。正しい列名は **「登録した方法」**。値の種類は「自動で経理」「決算」「手動」「減価償却」。`決算整理仕訳` は 0/1
  - 総勘定元帳: Shift_JIS（CP932）、1行目がタイトルで、ヘッダは2行目、24列。上の8列はすべて一致した。元帳のメモの列名は「メモタグ」
  - 仕訳帳には、使わない列として「借方決算書表示名」「〜ショートカット１／２」「部門」「品目」「セグメント１〜３」「取引ID」「期末日取引フラグ」「発行元」なども含まれる（列名の完全な一覧は `.tmp/freee-headers.txt`。コミットしない）
  - 元帳の開始行（2024〜2026年分）: `相手勘定科目` は「開始残高」（最初の年）か「前期繰越」。取引日は期首日（YYYY-MM-DD）、`決算整理仕訳 = 0`、借方金額・貸方金額・仕訳番号は空欄で、残高だけが入る

## R4. 仕訳の組み立てと正規化

- **Decision**:
  - `仕訳ID` でまとめ、`仕訳行番号` の順に並べる。行数が `仕訳行数` と違えば取込不可（`LINE_COUNT_MISMATCH`）
  - 各行の借方側・貸方側をそれぞれ1つの仕訳行にする（借方 → 貸方の順）。勘定科目が空の側は行にしない
  - 名前の照合（科目、補助科目、税区分、取引先、メモタグ）は NFKC で正規化し、前後の空白を除いてから行う。摘要（取引内容）と備考は元の文字のまま保存する
  - 摘要は行の `description` に、備考は重複を除いて改行でつなぎ、仕訳の `memo` に入れる
  - メモタグの列に複数のタグがある場合の区切り文字は分析メモにないため、R18 の確認で決める（それまでは列の値全体を1つのタグとして扱う）
    - **確認結果（T005）**: 2025年分では、値のある借方メモに文字・数字以外の記号（空白を含む）が1つもなく、貸方メモには値がなかった。**列の値全体を1つのタグとして扱う** ことで確定する
- **Rationale**: 001 の仕訳は「行 = 片側」の形なので、freee の「1行に両側」を片側ずつに分ける。正規化は照合だけに使い、元の文字を残す（Constitution II）

## R5. 年初付の決算振替の扱い

- **Decision**: 「`決算整理仕訳 = 1` かつ 日付が会計期間の開始日」の仕訳を **前年分の決算振替** と判定する。
  - 仕訳の取込では、既定で取込対象外（`PRIOR_YEAR_CLOSING`）にする。利用者は対象に含められるが、「損益」科目は帳簿に対応する科目がないため、含めると取込不可になる
  - 期首残高の案（R6）と照合（R7）では、この振替を期首に繰り込む
- **Rationale**: 001 の期首残高は「振替の後」の値（決算書の期首の貸借対照表と同じ）であり、001 は損益を仕訳から導出するため「損益」科目を持たない。期首残高と振替の両方を入れると二重になる
- **Alternatives**: 振替を仕訳として取り込み、期首残高を振替の前の値にする（期首の BS が決算書と合わず、損益の科目が必要になる）

例（合成の値）: 前期繰越が 元入金 1,000、事業主借 100、事業主貸 300、資産 1,400（事業主貸を除く）、前年の利益 600 のとき（借方 1,700 ＝ 貸方 1,100 ＋ 利益 600）、振替は「事業主借 100 / 元入金 100」「損益 600 / 元入金 600」「元入金 300 / 事業主貸 300」。期首残高の案は 元入金 1,400、事業主借 0、事業主貸 0、資産 1,400 となり、貸借が一致する。

## R6. 期首残高の案の作り方

- **Decision**: 元帳の各科目の開始行（「前期繰越」「開始残高」）の残高に、R5 の振替の行の借方・貸方を加え、「損益」科目は捨てる。対応表で帳簿の科目・補助科目に置き換えて合算し、科目の通常の側を正として、マイナスなら反対側にする（警告 `NEGATIVE_OPENING`）。結果は 001 の `validateOpeningBalances` で検証する
- **保存**: 新しい書き込みの経路は作らない。画面は案を 001 の期首残高の一括置換（`PUT .../opening-balances`）に渡す。登録済みの値との差（FR-020）と、前年度の帳簿の繰越との差（FR-020a）は、案を作るときに一緒に返す
- **Rationale**: 001 の期首残高の規則と変更履歴をそのまま使える（Constitution VII）
- **前年度の繰越（FR-020a）**: ドメインの純関数 `carryForward` で、前年度の期末残高から翌年度の期首を作る。収益・費用は所得として元入金に、事業主貸・事業主借は元入金に振り替えて 0 にする。科目は seed のコード（元入金 3020、事業主借 3010、事業主貸 3090）で特定する。これは決算処理の機能の繰越と同じ計算なので、その機能でも再利用する

## R7. 照合の比べ方

- **Decision**: 元帳の側は、開始行の残高に R5 の振替を繰り込んだ値を「期首」とし、振替の行を除いた借方・貸方の合計と、最終行の残高を「期末」とする。両側を **帳簿の科目**（補助科目は合算）にまとめて、期首・借方合計・貸方合計・期末の4つを比べる。freee の複数の科目が帳簿の1つの科目に対応する場合は合計で比べる。「損益」科目は比べない
- **差の原因の候補**（FR-023）: 取込対象外・取込不可にした仕訳、取り消した取込に含まれる仕訳のうち、その科目を含むものを一覧にする
- **Rationale**: 帳簿側は 001 の試算表の導出（`computeBalances`）をそのまま使える。期首の定義を両側でそろえることで、R5 の振替による差が出ない
- **Alternatives**: 補助科目の単位で比べる（元帳に補助科目の列がないため不可能）

## R8. 取込済みの判定（二重登録の防止）

- **Decision**: `import_journal_refs` に freee の仕訳ID と取込の回を持ち、「取り消されていない参照」について freee の仕訳ID を一意にする（部分一意インデックス `WHERE revoked_at IS NULL`）。プレビューではこの参照で「取込済み」を判定する。利用者が帳簿で個別に取り消した仕訳も、参照が残る限り取込済みとして扱う
- **Rationale**: 二重登録の防止を DB の制約でも担保する（Constitution I）。仕訳ID は1,000件超で一意だった（分析メモ）。freee 側の編集で ID が変わらないことは未確認のため、FR-029 の変更検出で異常に気づけるようにする

## R9. freee 側の変更・削除の検出（FR-029、FR-030）

- **Decision**: 取込のときに、正規化した freee の仕訳の内容（日付、各行の貸借・科目・補助科目・金額・税区分・取引先・メモタグ・摘要、備考）を正準化した JSON として参照に保存する。次の取込で同じ仕訳ID の内容と文字列で比べ、違えば `FREEE_CHANGED`（変更前後の内容つき）。ファイルの日付の範囲（選んだ年度の中の最小日〜最大日）に入る参照のうち、ファイルにないものは `FREEE_DELETED`
- **Rationale**: 帳簿側で利用者が訂正しても、比べる相手は「前回取り込んだときの freee の内容」なので誤検出しない

## R10. トランザクションの単位

- **Decision**: 取込の確定は、補助科目・取引先・メモタグの作成、仕訳と行の登録、監査ログ、取込の記録を **1つの SQLite トランザクション** で行う。001 のポートは `LedgerRepository` と `MasterRepository` が別々に `transaction` を持つため、両方をまとめる `ImportUnitOfWork` のポートを追加する（`packages/db` では同じ接続の上に両方のリポジトリを作る）
- **Rationale**: FR-012・SC-006（途中で失敗したら何も残さない）。better-sqlite3 の同期トランザクションで、例外でロールバックされる（001 の R1 で確認済み）

## R11. ファイルの受け渡し

- **Decision**: 画面から `multipart/form-data` でファイルを送る（Hono の `parseBody`、RPC クライアントの `form`）。サイズの上限は 5 MB（`bodyLimit`）。プレビューは **状態を持たない**: 確定のときも同じファイルを送り直し、サーバーでプレビューを作り直してから登録する。画面はプレビューで受け取ったファイルのハッシュ（SHA-256）を一緒に送り、一致しなければ `IMPORT_FILE_CHANGED`
- **Rationale**: 取込の途中の状態を DB に持たずに済む。1年分は数百 KB で、解析は1秒もかからない。ハッシュはサーバー（`node:crypto`）で計算し、取込の記録に残す（FR-018）。ファイル本体は保存しない（証憑の保存は別の機能）
- **Alternatives**: プレビューを DB に一時保存する（掃除と状態の管理が必要になる）

## R12. 監査ログ

- **Decision**: `audit_log` のスキーマは変えない。取り込んだ仕訳は `action = create` で記録し、`after_json` に `source: "import_freee"`、取込の回の ID、freee の仕訳ID を含める。取込の取消は、仕訳ごとに `action = void` と理由で記録する。取込の回そのものは `import_batches` に記録する
- **Rationale**: `audit_log` の CHECK 制約を変えるには、追記のみのテーブルを作り直す必要がある（SQLite は CHECK を ALTER できない）。仕訳の単位の記録で、Constitution II の「いつ・何を・なぜ」を満たせる
- **journals.source**: TypeScript の列挙に `import_freee` を加える（SQL の CHECK はないため、マイグレーションは不要）

## R13. 対応表の初期案

- **Decision**: ドメイン層の seed に、freee の名前から帳簿の科目コードへの既知の言い換えを置く。
  - 名前が帳簿の科目と同じ（NFKC 後）→ その科目
  - 言い換え: 交際費 → 接待交際費（5140）、その他口座 → 普通預金（1020）、事務用品費 → 消耗品費（5170。決算書では同じ欄）
  - 名前が「カード」で終わる科目 → 未払金（2020）＋同じ名前の補助科目（なければ作成）
  - 「損益」→ 対応なし（対応づけられない）
  - 税区分: 対象外 → `OUT_OF_SCOPE`、課税売上10% → `SALES_10`、課税売上8%（軽） → `SALES_8R`、課対仕入10% → `PURCHASE_10`、課対仕入8%（軽） → `PURCHASE_8R`。非課税・不課税の表記は分析メモにないため初期案を置かず、出てきたら利用者が選ぶ
- **補助科目**: 対応表の1行は「freee の科目名 → 帳簿の科目＋補助科目（任意）」。freee の補助科目名が科目名と同じなら無視し、違う場合は帳簿の科目の下の同じ名前の補助科目に対応させる（なければ作成）
- **保存**: 利用者が決めた対応は事業体の DB に保存し、次から初期案より優先する（FR-011）

## R14. 税額と税区分の検査

- **Decision**: 税額は 001 の INV-10（`computeInclusiveTax`、`tax_rates` から仕訳の日付で税率を引く）で計算し直して保存する。freee の税金額と違えば警告 `TAX_AMOUNT_MISMATCH`。費用の科目に売上の税区分、収益の科目に仕入の税区分が付いていれば警告 `TAX_CATEGORY_SUSPICIOUS`。どちらも取込は妨げない
- **Rationale**: 帳簿の税額は帳簿の規則で決める（Constitution VI）。税区分は自動では直さない（spec の Assumptions）

## R15. 仕訳番号の採番

- **Decision**: 取り込む仕訳は、日付 → freee の仕訳番号 → 仕訳ID の順に並べ、既存の最大の仕訳番号の次から採番する
- **Rationale**: 001 の INV-8（単調増加・重複なし）を守る。既存の仕訳より後に採番されるため、番号と日付の順が逆になることがあるが、帳票は日付順に並ぶ

## R16. 手入力の仕訳との重複の警告（FR-016）

- **Decision**: 取込の仕訳ごとに、同じ日付で、行の組（貸借・帳簿の科目・金額）の集合が同じ、手入力（`source = manual`）の有効な仕訳があれば `POSSIBLE_DUPLICATE`。001 の重複の警告と同じ比べ方にする

## R17. テストのフィクスチャ

- **Decision**: 匿名化した合成のフィクスチャを `packages/domain/test/fixtures/freee/` に置く。仕訳帳は UTF-8 の CSV、元帳は UTF-8 で書いた元を `iconv -f UTF-8 -t CP932` で変換した CP932 の CSV もコミットする（変換の手順をフィクスチャの README に書く）。内容は、複合仕訳、カード、源泉所得税の差引、年初付の決算振替、減価償却、片側が空の行、全角の英数字、マイナスの開始残高を含め、仕訳帳と元帳が互いに整合するように作る
- **プロパティテスト**: 任意の貸借一致の仕訳の列 → freee 形式の仕訳帳と元帳を生成 → 取込 → 照合がすべて一致、を arbitraries で検証する
- **Rationale**: Constitution V（実データの形式を模した匿名化フィクスチャで、元帳との突合までテストする。実データはリポジトリに含めない）

## R18. 実データでの照合（ローカル専用）

- **Decision**: `scripts/verify-freee-import.ts` を作る。引数で `work/` の仕訳帳と元帳のパスを受け取り、`.tmp/` の使い捨てのデータディレクトリに事業体を作って取り込み、ヘッダの照合結果（R3）、取込の件数、照合の結果、PL・BS の科目別の金額を標準出力に出す。出力はリポジトリに含めない
- **Rationale**: SC-003・SC-004 を実データで確かめつつ、実データをリポジトリに入れない（Constitution III, V）

## R19. 会計期間

- **Decision**: 取込で会計期間は作らない。001 は「翌年度の作成」しかできないため、2025年分を取り込むには、開始年度 2025 で事業体を作る。会計期間がない日付の仕訳は取込不可（`OUT_OF_PERIOD`）とし、最後の会計期間より後なら翌年度の作成を、最初の会計期間より前なら「事業体の開始年度より前」と案内する
- **Rationale**: 001 の会計期間の規則を変えない（範囲を広げない）

## R20. 画面

- **Decision**: 事業体のメニューに「取込」を加える。画面は、取込の履歴（`/e/$entityId/imports`）、新しい取込（ファイルの選択 → プレビュー・対応表・年度の選択 → 確定, `/imports/new`）、取込の詳細と取消（`/imports/$batchId`）、照合（`/imports/reconcile`）。期首残高の画面（001）に「freee の元帳から読み込む」を加える
- **テスト**: 001 と同じく Testing Library ＋ jsdom のコンポーネントテストと、Playwright の E2E 1本（フィクスチャの取込 → 照合がすべて一致）
