# Feature Specification: freee からのデータ取込

**Feature Branch**: `002-freee-import`

**Created**: 2026-10-19

**Status**: Draft

**Input**: User description: "002"（001 の spec の Assumptions で予定した「freee からのデータ取込」。これまで freee で付けてきた帳簿を、001 で作った帳簿へ移し、過去の青色申告決算書と照合できるようにする）

## User Scenarios & Testing *(mandatory)*

### User Story 1 - freee の仕訳帳を取り込む (Priority: P1)

利用者は、freee から書き出した仕訳帳のファイルを選ぶ。システムはファイルを読み、取り込む前に一覧（プレビュー）を示す。一覧には、仕訳の件数と期間、借方・貸方の合計、取り込めない仕訳とその理由、すでに取り込み済みの仕訳が表示される。freee の勘定科目・口座・税区分が帳簿のどの科目・補助科目・税区分になるかを示す対応表も表示され、対応が決まっていない項目があるうちは取り込めない。利用者が内容を確かめて「取り込む」を押すと、すべての仕訳が1回の操作でまとめて登録される。途中で失敗したときは、1件も登録されない。

**Why this priority**: 過去の帳簿を手で入力し直すのは現実的でない（2025年分で約500仕訳）。取込ができて初めて、帳簿を freee から乗り換えられる。

**Independent Test**: 匿名化した freee 形式の仕訳帳（複合仕訳、カード、源泉所得税の差引、決算仕訳を含む）を取り込み、仕訳帳と試算表の件数・金額がファイルと一致することで確認できる。

**Acceptance Scenarios**:

1. **Given** 2025年の会計期間がある事業体, **When** 利用者が2025年分の仕訳帳ファイルを選ぶ, **Then** 取り込む前に、仕訳の件数・期間・借方と貸方の合計・対応表・取り込めない仕訳の一覧が表示され、帳簿はまだ変わらない
2. **Given** プレビュー, **When** freee の科目「交際費」が帳簿の科目に対応づいていない, **Then** 利用者は既存の科目（例: 接待交際費）を選ぶか、新しい科目を作って対応づけるまで取り込めない
3. **Given** 1つの仕訳が4行からなる複合仕訳（例: 売掛金の入金で、普通預金・支払手数料・事業主貸に分かれる）, **When** 取り込む, **Then** 帳簿でも4行の1仕訳として登録され、行の順序と各行の科目・金額・税区分・摘要が保たれる
4. **Given** プレビューに問題がない, **When** 利用者が「取り込む」を押す, **Then** すべての仕訳がまとめて登録され、各仕訳に「freee から取込」という出所と freee の仕訳の識別子が記録される
5. **Given** 取り込み済みのファイル, **When** 同じファイルをもう一度選ぶ, **Then** すべての仕訳が「取込済み」と表示され、新しく登録される仕訳は0件になる
6. **Given** 締め済みの年度の日付を含むファイル, **When** プレビューを表示する, **Then** その仕訳は「締め済みの年度のため取り込めない」と表示され、取り込みの対象から外れる

---

### User Story 2 - 期首残高を freee から移す (Priority: P1)

利用者は、freee から書き出した総勘定元帳のファイルを選ぶ。システムは、各科目の期首の残高（「前期繰越」「開始残高」）を読み取り、帳簿の期首残高の案として示す。利用者は内容を確かめて保存する。借方と貸方の合計が一致しないときは保存できない。

**Why this priority**: 期首残高がないと、取り込んだ仕訳から作る貸借対照表が決算書と合わない。仕訳の取込（US1）と組み合わせて初めて、決算書との照合ができる。

**Independent Test**: 匿名化した freee 形式の総勘定元帳を読み、期首残高の案が元帳の前期繰越と一致し、保存後の期首の貸借対照表に反映されることで確認できる。

**Acceptance Scenarios**:

1. **Given** 期首残高が未登録の2025年度, **When** 利用者が総勘定元帳のファイルを選ぶ, **Then** 現金・預金（口座ごと）・売掛金・開業費・未払金（カードごと）・元入金などの期首残高の案が、US1 と同じ対応表で帳簿の科目・補助科目に置き換えて表示される
2. **Given** 期首残高の案, **When** 利用者が保存する, **Then** 001 の期首残高の登録と同じ規則（貸借一致、締め済みの年度は不可）で保存され、変更の履歴が残る
3. **Given** すでに期首残高が登録済み, **When** 案を保存しようとする, **Then** 現在の値と案の差が科目ごとに表示され、利用者が確かめてから置き換える
4. **Given** 元帳の期首残高にマイナスの科目がある（例: 売掛金 −15,000 円）, **When** 案を表示する, **Then** 反対側の残高として扱われ、警告が表示される

---

### User Story 3 - 取込の結果を元帳と照合する (Priority: P2)

取り込んだ後、利用者は照合レポートを開く。レポートは、帳簿から作った科目ごとの期首残高・借方合計・貸方合計・期末残高を、freee の総勘定元帳の値と並べて示し、一致しない科目を目立たせる。利用者はこのレポートで、取込に漏れや誤りがないことを確かめてから、青色申告決算書と見比べる。

**Why this priority**: 取込の正しさを人が全件見て確かめるのは難しい。元帳との突合で、漏れ・二重登録・対応表の誤りを一度に見つけられる。ただし、取込（US1・US2）がなければ照合するものがないため P2 とする。

**Independent Test**: 匿名化した仕訳帳と元帳を取り込み、全科目が「一致」になること、また1件の仕訳をわざと外したときにその科目が「不一致」になり差額が表示されることで確認できる。

**Acceptance Scenarios**:

1. **Given** 2025年分の仕訳と期首残高を取り込んだ事業体, **When** 利用者が同じ年の総勘定元帳を指定して照合する, **Then** 科目ごとに帳簿と元帳の期首残高・借方合計・貸方合計・期末残高が並び、すべて一致すれば「一致」と表示される
2. **Given** 一致しない科目がある, **When** 利用者がその科目を開く, **Then** 差額と、差の原因の候補（取り込まなかった仕訳、対応表で別の科目に移した金額など）が表示される
3. **Given** freee の複数の科目を帳簿の1つの科目にまとめた（例: 「事務用品費」を「消耗品費」に対応づけた）, **When** 照合する, **Then** まとめた科目どうしの合計で比較され、対応表による差は不一致として扱われない

---

### User Story 4 - 取込を取り消す (Priority: P2)

対応表の誤りなどに気づいたとき、利用者は取込の履歴から1回分の取込を選び、まとめて取り消す。取り消した仕訳は削除されず「取消」の状態になり、理由とともに履歴に残る。取り消した後は、対応表を直して同じファイルを取り込み直せる。

**Why this priority**: 取込は件数が多く、1件ずつ取り消すのは現実的でない。ただし、正しく取り込めれば使わない機能なので P2 とする。

**Independent Test**: 取り込んだ後に取り消し、仕訳帳・試算表から取込分が消え、変更履歴に取消が残り、同じファイルを再び取り込めることで確認できる。

**Acceptance Scenarios**:

1. **Given** 1回分の取込, **When** 利用者が理由を入力して取り消す, **Then** その取込で登録したすべての仕訳が取消の状態になり、帳票から除かれ、変更履歴に理由とともに記録される
2. **Given** 取込で登録した仕訳のうち、取込の後に利用者が訂正したものがある, **When** 取り消そうとする, **Then** 訂正済みの仕訳の件数が表示され、利用者が確かめてから取り消す
3. **Given** 取り込んだ年度が締め済み, **When** 取り消そうとする, **Then** 取り消せず、先に締めを解除する必要があると表示される
4. **Given** 取り消した取込, **When** 同じファイルをもう一度選ぶ, **Then** 仕訳は「取込済み」と判定されず、改めて取り込める

---

### User Story 5 - 同じ年度を繰り返し取り込む（並行稼働） (Priority: P3)

利用者は、freee での記帳を続けながら、月に1回程度、その年の最新の仕訳帳を取り込む。前回までに取り込んだ仕訳は登録されず、新しく増えた仕訳だけが登録される。freee 側で後から変更・削除された仕訳は、帳簿を自動では変えず、警告として一覧に出す。利用者は必要に応じて、帳簿の仕訳を自分で訂正・取消する。

**Why this priority**: 乗り換えの途中で両方の帳簿を使う期間がある場合に必要になる。過去の年度の移行（US1〜US4）だけなら不要。

**Independent Test**: 9月末までの仕訳帳を取り込んだ後、10月末までの仕訳帳を取り込み、10月分だけが新しく登録されることで確認できる。

**Acceptance Scenarios**:

1. **Given** 9月末までを取り込み済み, **When** 10月末までのファイルを取り込む, **Then** 10月分の仕訳だけが新規として表示・登録される
2. **Given** 取り込み済みの仕訳が freee 側で金額を直されている, **When** 新しいファイルのプレビューを表示する, **Then** その仕訳は「freee 側で変更あり」と、変更前後の内容とともに警告に表示され、帳簿の仕訳は変わらない
3. **Given** 取り込み済みの仕訳が freee 側で削除されている（新しいファイルの期間内にあるはずの仕訳がない）, **When** プレビューを表示する, **Then** その仕訳は「freee 側で削除」と警告に表示され、帳簿の仕訳は変わらない

---

### Edge Cases

- ファイルの種類や文字コードが想定と違う（freee 以外の CSV、仕訳帳と元帳の取り違え）: 取り込まず、どのファイルを選ぶべきかを表示する
- 全角の英数字・空白が混じった科目名・摘要: 半角にそろえてから対応表と照らし合わせる。摘要は元の文字のまま保存する
- 1つの仕訳の中で行の数がそろっていない、または借方と貸方の合計が合わない: その仕訳を取り込めない仕訳として表示する（他の仕訳の取込は妨げない）
- 金額に小数・マイナス・空欄がある行: その仕訳を取り込めない仕訳として表示する
- 仕訳の日付が、事業体のどの会計期間にも入らない: 取り込めない仕訳として表示し、会計期間の作成を提案する
- 年初の日付で、前の年の決算整理として作られた仕訳（例: 2025/01/01 付の2024年分の決算仕訳）: 期首残高に反映済みのため、既定で取込の対象から外し、利用者が個別に含められる
- freee の「損益」科目を使う振替: 帳簿では仕訳から損益を導出するため、既定で取込の対象から外す
- 帳簿にすでに手で入力した仕訳と、同じ日付・同じ金額・同じ科目の仕訳がある: 取込は妨げず、二重登録の可能性として警告する
- freee の税区分が科目と合わない（例: 費用の科目に「課税売上10%」）: 取込は妨げず、警告の一覧に出す。税区分は freee の値のまま対応表で置き換える
- freee の税区分に、対応表で未定義のもの（非課税、不課税など）が出てきた: 対応づけるまで取り込めない
- 取引先・メモタグ・補助科目が帳簿にない: プレビューで「新しく作るもの」として一覧し、取込と同時に作る
- 対応表で選んだ科目が無効（使用停止）になっている: 取り込めず、別の科目を選ぶよう表示する
- 取込の途中でアプリが終了した: 1件も登録されていない状態に戻る
- 取り込んだ仕訳を利用者が訂正した後に、同じファイルを取り込む: 訂正済みでも「取込済み」と判定し、二重に登録しない

## Requirements *(mandatory)*

### Functional Requirements

**読み込みとプレビュー**

- **FR-001**: システムは MUST、freee から書き出した仕訳帳のファイルと総勘定元帳のファイルを読み込める。仕訳帳と元帳はそれぞれの文字コードと列の並びを自動で判別し、それ以外のファイルは理由を示して受け付けない
- **FR-002**: システムは MUST、仕訳帳の複数の行のうち freee の同じ仕訳に属するものを1つの仕訳としてまとめ、行の順序を保つ
- **FR-003**: システムは MUST、取り込む前にプレビューを示す。プレビューには、仕訳の件数と期間、借方と貸方の合計、新規・取込済み・取込対象外・取込不可の件数と一覧、新しく作る補助科目・取引先・メモタグ、警告の一覧を含める
- **FR-004**: システムは MUST、プレビューの段階では帳簿を変更しない
- **FR-004a**: 利用者は MUST、プレビューで、ファイルに含まれる年度ごとに取り込むかどうかを選べる。システムは取り込む年度を固定しない（例: 2025年分だけ、2025年分と2026年分の両方）
- **FR-005**: システムは MUST、次の仕訳を「取込不可」とし、理由を示す: 借方と貸方の合計が合わない、金額が正の整数でない、日付がどの会計期間にも入らない、日付が締め済みの年度にある、必須の項目が欠けている
- **FR-006**: システムは MUST、年初の日付で前年の決算整理として作られた仕訳と、「損益」科目への振替を「取込対象外（既定）」として示し、利用者が仕訳ごとに対象に含められるようにする

**対応表**

- **FR-007**: システムは MUST、freee の勘定科目・口座（銀行口座、クレジットカードなど）・税区分を、帳簿の勘定科目・補助科目・税区分に置き換える対応表を、事業体ごとに持つ
- **FR-008**: システムは MUST、対応表の初期案を示す。名前が同じか、既知の言い換え（例: 交際費→接待交際費、その他口座→普通預金、各カード→未払金の補助科目）に当たる場合は自動で案を出し、案は利用者が変えられる
- **FR-009**: システムは MUST、ファイルに出てくる科目・口座・税区分のうち、1つでも対応が決まっていないものがあれば取り込めないようにする
- **FR-010**: 利用者は MUST、対応表の中で、帳簿に新しい勘定科目を作り、決算書の欄に対応づけてから選べる
- **FR-011**: システムは MUST、利用者が決めた対応表を保存し、次の取込で再び使う

**登録**

- **FR-012**: システムは MUST、取込を1回の操作として扱い、すべての仕訳・新しい補助科目・取引先・メモタグの登録が成功したときだけ確定する。1件でも失敗したときは何も登録しない
- **FR-013**: システムは MUST、取り込んだ仕訳を、001 の手入力の仕訳と同じ規則（貸借一致、金額は円の整数、締め済みの年度は変更不可）で検証してから登録する
- **FR-014**: システムは MUST、取り込んだ仕訳ごとに、出所（freee からの取込）、取込の回、freee の仕訳の識別子と行番号を記録し、変更履歴に取込の記録を残す
- **FR-015**: システムは MUST、freee の仕訳の識別子と行番号で取込済みかどうかを判定し、取り消されていない取込済みの仕訳を二重に登録しない
- **FR-016**: システムは MUST、日付・金額・科目が同じ手入力の仕訳がすでにある場合、二重登録の可能性として警告する（登録は妨げない）
- **FR-017**: システムは MUST、取り込んだ仕訳を、001 の仕訳と同じように表示・検索・訂正・取消できるようにする。帳票では手入力の仕訳と区別せずに集計する
- **FR-018**: システムは MUST、取り込んだファイルの内容を識別できる値（内容のハッシュ）、ファイル名、取込の日時、件数を取込の履歴として残す

**期首残高**

- **FR-019**: システムは MUST、総勘定元帳の各科目の期首の残高（前期繰越・開始残高）を読み取り、対応表で置き換えて、期首残高の案として示す
- **FR-020**: システムは MUST、期首残高の案の保存に、001 の期首残高と同じ規則（貸借一致、締め済みの年度は不可、変更履歴）を適用する。登録済みの値がある場合は、科目ごとの差を示してから置き換える
- **FR-020a**: システムは MUST、前の年度の仕訳が帳簿にある場合、期首残高の案と、前の年度の帳簿から求めた期末残高（元入金は、元入金＋所得＋事業主借−事業主貸に置き換えたもの）を科目ごとに比べ、差がある科目を警告する（保存は妨げない）

**照合**

- **FR-021**: システムは MUST、指定した年度について、帳簿の科目ごとの期首残高・借方合計・貸方合計・期末残高を、総勘定元帳のファイルの値と並べて示し、一致・不一致を表示する
- **FR-022**: システムは MUST、照合の比較を対応表に沿って行う。freee の複数の科目を帳簿の1つの科目にまとめた場合は、まとめた合計で比較する
- **FR-023**: システムは MUST、不一致の科目について、差額と、差の原因の候補（取込対象外・取込不可にした仕訳、取り消した取込）を示す。照合は取込のときの選択を参照しないため、利用者が取込のときに対象から外した仕訳は「取込対象外」でなく「未取込」として示す（許容する。帳簿にない仕訳であることは同じで、差額の説明には足りる）

**取消**

- **FR-024**: 利用者は MUST、取込の履歴から1回分の取込を選び、理由を入力して、その取込で登録したすべての仕訳をまとめて取り消せる。取消は 001 の仕訳の取消と同じく、削除せず履歴に残す
- **FR-025**: システムは MUST、締め済みの年度の仕訳を含む取込の取消を拒否し、締めの解除が必要なことを示す
- **FR-026**: システムは MUST、取り込んだ後に訂正された仕訳がある取込を取り消すとき、その件数を示して確認を求める
- **FR-027**: システムは MUST、取込の取消で、その取込で作った補助科目・取引先・メモタグと対応表は残す

**並行稼働**

- **FR-028**: システムは MUST、同じ年度の新しいファイルを取り込むとき、前回までに取り込んだ仕訳を除いて新しい仕訳だけを登録する
- **FR-029**: システムは MUST、取り込み済みの仕訳と同じ識別子の仕訳の内容（日付、科目、金額、税区分、摘要）が、前回取り込んだときの freee の内容から変わっている場合（帳簿側で利用者が訂正した内容とは比べない）、「freee 側で変更あり」として変更前後の内容を警告に出す。帳簿の仕訳は変更しない
- **FR-030**: システムは MUST、取り込み済みの仕訳のうち、日付が新しいファイルの期間内にあるのにファイルにないものを「freee 側で削除」として警告に出す。帳簿の仕訳は変更しない

### Key Entities *(include if feature involves data)*

- **取込（Import Batch）**: 1回分の取込。事業体、ファイルの種類、ファイル名、内容のハッシュ、取込の日時、対象の期間、件数（新規・取込済み・対象外・不可）、状態（確定・取消）、取消の理由を持つ
- **取込元の仕訳の識別（Source Reference）**: 帳簿の仕訳と freee の仕訳を結ぶ。freee の仕訳の識別子と行番号、どの取込で登録したかを持つ。二重登録の判定と取消に使う
- **対応表（Mapping）**: 事業体ごとに、freee の勘定科目・口座・税区分の名前と、帳簿の勘定科目・補助科目・税区分の組を持つ。利用者が決めた日時を持つ
- **期首残高の案（Opening Balance Proposal）**: 元帳から読み取った科目ごとの期首残高を、対応表で置き換えたもの。保存すると 001 の期首残高になる
- **照合結果（Reconciliation Result）**: 年度、科目ごとの帳簿の値と元帳の値（期首残高、借方合計、貸方合計、期末残高）、一致・不一致、差額。保存せず、表示のたびに作る

## Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-001**: 2025年分の仕訳帳と総勘定元帳（約500仕訳）を、対応表の作成を含めて、初めての取込でも30分以内に取り込み、照合を終えられる
- **SC-002**: 1年分（約500仕訳）のファイルを選んでからプレビューが表示されるまで5秒以内、「取り込む」を押してから完了まで10秒以内
- **SC-003**: 2025年分を取り込んだ後の照合で、総勘定元帳と全科目（対応表でまとめた科目は合計）の期首残高・借方合計・貸方合計・期末残高が一致する
- **SC-004**: 2025年分を取り込んだ後の損益計算書と貸借対照表の各科目の金額が、2025年分の青色申告決算書（R7）の金額と一致する（001 の SC-008 をこの機能の完了時に検証する）
- **SC-005**: 同じファイルを2回取り込んでも、仕訳の件数と帳票の金額が1回目と変わらない
- **SC-006**: 取込の途中で失敗させたとき、帳簿の仕訳・期首残高・マスタが取込の前と完全に同じである
- **SC-007**: 取込を取り消した後の帳票の金額が、取込の前と一致し、取り消した仕訳がすべて変更履歴で確認できる

## Assumptions

- 取込の対象は freee の「仕訳帳」と「総勘定元帳」の書き出しファイル（CSV）とする。freee の「取引」の書き出しや、freee の API との連携は範囲外。分析した書き出しでは、仕訳帳は103列・UTF-8、元帳は24列・Shift_JIS 系で、ヘッダの前にタイトル行がある
- 取り込む年度は、利用者がプレビューで選ぶ（利用者の確認, 2026-10-19）。決算書との照合（SC-003、SC-004）は 2025年分（R7）で行う。freee の 2024年分は R6 の決算書と金額が大きく異なり、2023年分のデータはないため、2024年以前は照合の対象にしない
- 期首残高は、年度ごとにその年の総勘定元帳から読み込む。001 には期首残高を前年度から自動で繰り越す機能がないため、2026年分を取り込む場合も 2026年の元帳を使い、前年度の帳簿の期末残高との差を警告で確かめる（FR-020a）。自動の繰越は決算処理の機能（別の機能）で扱う
- 並行稼働では、freee 側の変更・削除を警告するだけで、帳簿は自動で直さない（利用者の確認, 2026-10-19）
- 2025年の期首残高は、freee の元帳の前期繰越（2024年末の残高）を使う。分析では、この値は R7 の決算書の期首の貸借対照表と一致している
- 税区分は freee の値を対応表で置き換えて保存し、自動では直さない。分析では費用の科目に「課税売上10%」が付いた仕訳が2025年に52件あるが、事業者は免税・税込経理のため、帳票の金額には影響しない。警告として一覧に出し、直すかどうかは利用者が後から仕訳を訂正して決める
- freee のメモタグは帳簿のメモタグに、取引先は帳簿の取引先に、備考は摘要とは別のメモとして取り込む。freee の部門・品目は使われていないため範囲外
- 家事按分は freee でも仕訳になっておらず、取込で按分の仕訳は作らない。按分は決算処理の機能（別の機能）で扱う
- freee の仕訳の識別子は、freee 側で仕訳を編集しても変わらない前提とする（書き出しファイルだけでは確認できないため、並行稼働の要否の確認とあわせて確かめる）
- 取込に使ったファイルは、取込の履歴にハッシュとファイル名を残す。ファイルそのものの保管は、証憑の保存の機能（別の機能）で扱う
- テストでは、実データ（`work/`）を模した匿名化したファイルを使う。実データでの照合（SC-003、SC-004）は、利用者の Mac 上で行い、結果をリポジトリに含めない
- 認証とバックアップは後の機能で扱う
