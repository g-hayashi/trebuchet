# Quickstart: 004-auth-backup の動作確認

仕様は [spec.md](./spec.md)、API は [contracts/http-api.md](./contracts/http-api.md)、復元のコマンドは [contracts/cli.md](./contracts/cli.md)、不変条件は [data-model.md](./data-model.md) §4。鍵まわり（回復キー、DK、バックアップの鍵）は 008 で置き換わった（[ADR 0011](../../docs/adr/0011-passkey-prf-vault.md)、AGENTS.md の「008」の節）。この文書は 008 以降の形で、画面の文言は `apps/web/src/features/` の実装に合わせてある。

**注意**: Claude Code のサンドボックスではローカルのポートを開けないため、§2・§3 の確認と E2E は利用者の端末で server を起動して行う。パスキーは PRF に対応したもの（iCloud キーチェーン、1Password など）が要る。

## 2. 手動での確認（利用者の端末）

```bash
TREBUCHET_DATA_DIR="$PWD/.tmp/quickstart-004" pnpm dev    # http://localhost:5173
```

1. **初回の設定（US1）**: http://localhost:5173 を開く → 「初回の設定」→「パスキーを作成」→ Touch ID（PRF に対応したパスキー。対応していなければ登録できない）→ 「回復キー」が表示される。紙に書き写し、「回復キーを安全な場所に保管しました」にチェックを入れるまで「続ける」を押せない。回復キーは、この画面を閉じると二度と表示されない
2. **解錠（US1）**: 設定（ヘッダーのリンク）→ セキュリティ →「施錠」→ 「帳簿は施錠されています」→ 「パスキーで解錠」→ Touch ID で帳簿の画面に戻る。施錠中は `curl -i http://127.0.0.1:8787/api/entities` が 401（セッションがあって施錠中の API は 401 `LOCKED`）
3. **回復キーでの解錠（US1）**: 施錠 → 「回復キーで解錠」→ 控えた回復キーを入れて「回復キーを確認」→ 10分以内に「新しいパスキーを登録」→ 新しい回復キーが表示される（保管の確認は手順1と同じ）。使った回復キーは無効になる。設定 → セキュリティの「回復キーを作り直す」（パスキーで再認証が要る）でも新しいキーが出て、古いキーは使えなくなる
4. **バックアップ（US2）**: バックアップ（ヘッダーのリンク）→「置き場所の設定」で `.tmp/quickstart-004-backup/` を入れて「保存」→ 最初のバックアップが始まり、成功してファイルができる。パスフレーズはない（鍵はこの Mac のデータ鍵から作る）。「今すぐバックアップ」は内容が同じでも必ずファイルを書く。自動の判断（24時間後）は、帳簿を変えていなければ「変更なし」になる（確認は自動テストと、置き場所のファイルを手で消した後の挙動で行う）。自動のバックアップは解錠中だけ動く
5. **失敗の知らせ（US2）**: 置き場所のフォルダを消して「今すぐバックアップ」→ 失敗と理由が表示され、画面の上部に知らせが出る
6. **検査（US3）**: バックアップ →「復元」→ バックアップのファイルを選んで「検査」→ 作成日時・事業体ごとの年度と仕訳の件数の要約と「復元の手順」が出る（解錠中の鍵で検査するので、この Mac のデータ鍵で取ったファイルだけが対象。ほかの鍵のファイルや壊れたファイルは検査に失敗する）
7. **復元（US3）**: server を止め、`pnpm restore -- --file .tmp/quickstart-004-backup/<ファイル> --data-dir .tmp/quickstart-004-restored` → 要約が出る → 回復キーを標準入力から入力（画面には出ない）→ 確認 → 成功。`TREBUCHET_DATA_DIR=.tmp/quickstart-004-restored pnpm dev` で開くと、「帳簿は施錠されています」から「回復キーで解錠」→ 新しいパスキーを登録（手順3と同じ）→ 登録後の帳簿が元と同じ。復元した `auth.sqlite` は回復キーの包みだけなので、パスキーは登録し直す。バックアップの置き場所やリモートの設定は復元されないので、設定し直す。回復キーを間違えると「回復キーが違うか、ファイルが壊れています」
8. **時間（SC-008）**: 手順7（新しい場所への復元〔`pnpm restore`、回復キー〕とパスキーの登録）にかかった時間を計る。15分以内が目安

## 3. Tailscale 経由の確認（US4、利用者の端末）

> US4 は 2026-11-02 に 008 の形で再開した。手順は README の「スマホから使う」と同じ。ペアリングは「リモート」の画面にある（パスキーの一覧ではない）。Funnel は使わない。

```bash
pnpm start                                                 # http://localhost:8787
```

1. Mac で `http://localhost:8787` を開いて解錠する。ヘッダーの「リモート」を開く。
2. 「Tailscale」の欄で状態を見る（「Tailscale はインストールされていません」「Tailscale は停止中です」「Tailscale に接続中：<名前>」）。接続中なら「開始」で serve を始める（「公開中：https://<machine>.<tailnet>.ts.net」と出る。止めるときは「停止」）。画面を使わずに行うなら、「手動で行う場合」の `tailscale serve --bg --https=443 http://127.0.0.1:8787`（止めるのは `tailscale serve --https=443 off`、または `tailscale serve reset`）。
3. 「リモートの設定」で「リモートを有効にする」にチェック、「ts.net の名前」に `<machine>.<tailnet>.ts.net`（「この Mac の名前を入れる」で入る）→「保存」。再起動は要らない。
4. 「ペアリング」の欄で「この名前で使うパスキーを追加（ペアリング）」→ パスキーで再認証 → ペアリングの URL（`https://<machine>.<tailnet>.ts.net/pair?token=…`）と QR コードが出る。10分有効、一度だけ、画面を閉じると二度と表示されない。
5. iPhone（同じ tailnet）で QR コードを読むか URL を開く →「このスマホのパスキーを登録」→ 登録（PRF に対応していないパスキーは「鍵の保護（PRF）に対応していません」で失敗する。iCloud キーチェーンなどを使う）→ `https://<machine>.<tailnet>.ts.net` でパスキーで解錠・サインインできる。同じ URL をもう一度開くと「ペアリングの URL が無効か期限切れです」になる
6. ts.net の名前から、ペアリングの URL なしでパスキーを登録しようとしても拒否される（初回の設定も localhost からだけ）
7. Mac を施錠する（セキュリティ →「施錠」）→ ts.net の名前では使えない（401 `LOCKED`）。Mac で解錠すると使える。ペアリングの URL を開いても、施錠中は「Mac でアプリを解錠してください」になる
8. 「リモートを有効にする」を外して保存 → iPhone からの接続が拒否される
9. 確認が終わったら、「停止」を押す（手動なら `tailscale serve reset`）
