## User Scenarios & Testing *(mandatory)*

### User Story 1 - パスキーで帳簿を守る (Priority: P1)

利用者は初めてアプリを開くと、パスキー（Mac の Touch ID）を登録するよう求められる。登録の後は、アプリを開くたびにパスキーでサインインしないと、帳簿のデータを見ることも API を使うこともできない。登録のときに一度だけ表示される回復コードを控えておけば、パスキーをすべて失っても帳簿に戻れる。iPhone など別の端末のパスキーも追加できる。

**Why this priority**: 帳簿・決算書・申告の控えには個人の所得と取引先の情報が入っている。同じ Mac の別のアプリや、ネットワーク上の別の端末から読まれないようにすることが、リモートのアクセスやスマホからの利用の前提になる。

**Independent Test**: 新しいデータ場所でアプリを開き、パスキーの登録 → サインアウト → サインインを行う。サインインしていない状態で、帳簿のデータを返すすべての入口（API とファイルの出力）が拒否されることを確かめる。回復コードで新しいパスキーを登録し直せることを確かめる。

**Acceptance Scenarios**:

1. **Given** パスキーが1つも登録されていない, **When** 利用者が Mac のローカルの名前でアプリを開く, **Then** 帳簿の画面ではなくパスキーの登録の画面が表示され、登録を終えると回復コードが一度だけ表示される。利用者が「控えた」と確認するまで次に進めない
2. **Given** パスキーが登録済み, **When** 利用者がサインインしていない状態でアプリを開く, **Then** サインインの画面が表示され、パスキーで認証すると帳簿の画面に進む
3. **Given** サインインしていない, **When** 帳簿の API を直接呼ぶ, **Then** すべて拒否され、帳簿のデータは返らない
4. **Given** サインイン済み, **When** 一定時間（既定 8時間）操作しない, **Then** セッションが切れ、次の操作でサインインを求められる
5. **Given** サインイン済み, **When** 利用者が設定の画面で別の端末のパスキーを追加する, **Then** その端末でもサインインできる。登録済みのパスキーの一覧（名前、登録日、最後に使った日）が表示され、名前を変えたり削除したりできる。パスキーを削除すると、そのパスキーでサインインしていたセッションも無効になる
6. **Given** `localhost` のパスキーを1つだけ登録している, **When** 利用者がそのパスキーを削除しようとする, **Then** `localhost` の最後の1つは削除できないことが示される。Tailscale の名前（ts.net）のパスキーは、すべて削除できる
7. **Given** パスキーをすべて失った, **When** 利用者がサインインの画面で正しい回復コードを入力する, **Then** 10分間だけ有効な回復用の画面に進み、新しいパスキーを登録できる（途中で中断しても10分の間はやり直せる）。新しいパスキーの登録が成功したときに、使った回復コードが無効になり、新しい回復コードが一度だけ表示される。回復コードの入力だけでは帳簿の画面に入れない
8. **Given** サインイン済み, **When** 利用者がサインアウトする, **Then** その端末のセッションが終わり、サインインの画面に戻る
9. **Given** サインイン済み, **When** 利用者が回復コードを作り直す, **Then** 新しい回復コードが一度だけ表示され、古い回復コードは使えなくなる（FR-007）
10. **Given** 登録・サインイン（成功と失敗）・回復・パスキーの削除・セッションの無効化・ペアリング・リモートの設定の変更が行われた, **When** 利用者が設定の画面で認証の記録を見る, **Then** 日時・接続先の名前・端末の情報つきで新しい順に並び、記録を書き換えることも消すこともできない（FR-008）
11. **Given** サインイン済みの利用者のブラウザ, **When** 別のサイトから、帳簿を変える要求（本文が JSON の POST、本文のない DELETE を含む）が送られる, **Then** 拒否され、帳簿は変わらない（FR-009）

### User Story 2 - 暗号化したバックアップを毎日取る (Priority: P1)

利用者は設定の画面で、バックアップのパスフレーズを2回入力し、バックアップの置き場所として Google Drive の同期フォルダを選ぶ。パスフレーズを忘れるとバックアップを復元できないことが、はっきり示される。以後、アプリが動いている間に1日1回、帳簿に変更があればバックアップが自動で取られ、暗号化したファイルが同期フォルダに置かれる。利用者はいつでも手動でバックアップを取れ、最後に成功した日時と、失敗したときの理由を画面で確かめられる。

**Why this priority**: 帳簿は7年以上保存する義務があり（Constitution II）、Mac の故障や誤操作でデータを失うと取り戻せない。003 までで決算と申告の控えまで帳簿に入るようになったため、失う危険が大きくなった。

**Independent Test**: 合成のデータでパスフレーズと置き場所を設定し、手動のバックアップ、自動のバックアップ（時刻を進める）、変更がない日の省略、世代の整理、置き場所がないときの失敗の表示を確かめる。バックアップのファイルがパスフレーズなしでは読めないことを確かめる。

**Acceptance Scenarios**:

1. **Given** バックアップが未設定, **When** 利用者がパスフレーズを2回入力し、同期フォルダを選んで保存する, **Then** 「パスフレーズを忘れると復元できません」の確認に同意したあとで設定が保存され、すぐに最初のバックアップが取られる
2. **Given** 2回のパスフレーズが一致しない、または短すぎる（12文字未満）, **When** 保存する, **Then** 保存できず、理由が示される
3. **Given** バックアップが設定済み, **When** 利用者が「今すぐバックアップ」を押す, **Then** 帳簿に変更がなくても、すべての事業体の帳簿を含む暗号化したファイルが置き場所に作られ、最後の成功の日時が更新される
4. **Given** 前回の確認（成功、または変更なしの記録）から24時間以上たち、アプリが動いている, **When** 自動のバックアップの判断が行われる, **Then** 帳簿の内容が前回の成功と変わっていればファイルを書く。変わっておらず、前回の成功のファイルが今の置き場所にあり、パスフレーズを変えていなければ、ファイルを書かず「変更なし」と記録する。「変更なし」は新しい「前回の確認」になる
5. **Given** 置き場所のフォルダが見つからない（同期アプリが止まっている、ディスクが外れているなど）, **When** バックアップを取る, **Then** 失敗し、理由と日時が画面に示され、帳簿の画面の上部にバックアップの失敗が知らされる
6. **Given** 置き場所に古いバックアップがたまっている, **When** 新しいバックアップを取る, **Then** 直近の30日分の毎日の世代と、それより前の各月の最後の世代（最大7年）を残し、ほかは置き場所から削除する
7. **Given** バックアップのファイル, **When** パスフレーズを知らない人がファイルを開く, **Then** 帳簿の内容（取引先名、金額など）は読めない
8. **Given** バックアップが設定済み, **When** 利用者がパスフレーズを変える, **Then** 以後のバックアップは新しいパスフレーズで暗号化され（変更の直後に、内容が同じでも新しいパスフレーズでバックアップが書き直される）、古いバックアップには古いパスフレーズが要ることが示される
9. **Given** バックアップが設定済み, **When** データの場所・リポジトリ・アプリの設定・バックアップの記録を調べる, **Then** どこにもパスフレーズは平文で残っておらず、macOS のキーチェーン（使えないときはメモリ）にだけある（FR-015）
10. **Given** バックアップのファイルを書いた直後, **When** 同じパスフレーズで読み戻した内容が壊れている（検証に失敗する）, **Then** そのバックアップは失敗として記録され、最終の名前のファイルは置き場所に残らない（FR-022）

### User Story 3 - バックアップから復元する (Priority: P1)

Mac を買い替えたとき、または帳簿を誤って壊したとき、利用者はバックアップのファイルとパスフレーズを指定して帳簿を復元する。復元の前に、ファイルが壊れていないこととパスフレーズが正しいことが確かめられ、復元される内容（事業体、年度、仕訳の件数、バックアップの日時）が示される。今の帳簿を上書きするときは、上書きの前に今の帳簿が自動でバックアップされる。

**Why this priority**: 復元できないバックアップは意味がない（NFR-06「復元手順をテストする」）。

**Independent Test**: 合成のデータでバックアップを取り、新しいデータ場所に復元して、すべての事業体の帳簿（仕訳、履歴、期首残高、決算の登録、取込の記録）が元と完全に一致することを確かめる。事業体が0件のバックアップも往復できることを確かめる。誤ったパスフレーズ、壊れたファイル、版の違うアプリで作ったファイルを拒否することを確かめる。

**Acceptance Scenarios**:

1. **Given** バックアップのファイルとパスフレーズ, **When** 利用者が空のデータ場所（新しい Mac）で復元を選ぶ, **Then** 復元される内容の要約が示され、確定するとすべての事業体の帳簿が元どおりになる
2. **Given** 帳簿が入っているデータ場所, **When** 利用者が復元を確定する, **Then** 上書きの前に今の帳簿のバックアップが取られ、その場所が示されてから復元される。復元先に同じ事業体がすでにあれば、確認の前に事業体ごとの差（仕訳の件数、最後の更新）が示される
3. **Given** 誤ったパスフレーズ, **When** 復元を選ぶ, **Then** 「パスフレーズが違うか、ファイルが壊れています」と示され、帳簿は変わらない
4. **Given** 途中で壊れたファイル, **When** 復元を選ぶ, **Then** 復元の前に検知され、帳簿は変わらない
5. **Given** アプリの版（registry と事業体の帳簿の形式の版）が今のアプリと一致しないバックアップ（今より新しくても古くても）, **When** 復元を選ぶ, **Then** 版が一致しないことが示され、帳簿は変わらない（開発中は、帳簿の形式を更新しての復元はしない）
6. **Given** 復元の途中で失敗した, **When** 復元が止まる, **Then** 帳簿は復元を始める前の状態のまま残り、展開した一時の場所は消える
7. **Given** パスキーを登録していない新しい Mac, **When** 復元する, **Then** パスキーの登録・回復コード・アプリの設定（バックアップの置き場所、リモートの設定など）は復元されず、新しい Mac で登録・設定し直すことが示される（パスキーと設定は端末に結びつくため）

### User Story 4 - Tailscale 経由で外からサインインする (Priority: P2)

利用者は自宅の Mac で動くアプリに、外出先の iPhone や別の PC から Tailscale 経由でつなぐ。Tailscale の HTTPS の名前でアプリを開き、その名前に登録したパスキーでサインインする。その名前のパスキーは、Mac でサインインして発行した一度だけ使えるペアリングの URL から登録する。Tailscale のネットワークの外からはアプリに届かない。

**Why this priority**: スマホから帳簿を確かめたり、後のフェーズで証憑をアップロードしたりする前提になる（NFR-02）。Mac の上だけで使う間は不要なので P2 とする。

**Independent Test**: Tailscale の HTTPS の名前でアプリを開き、ペアリングの URL からその名前でパスキーを登録してサインインできること、Mac のローカルの名前で登録したパスキーとは別に管理されること、HTTPS でない接続や想定外の名前からの接続が拒否されることを確かめる。

**Acceptance Scenarios**:

1. **Given** 利用者が設定の画面でリモートのアクセスを有効にし、Tailscale の HTTPS の名前を登録した, **When** iPhone からその名前でアプリを開く, **Then** サインインの画面が表示される
2. **Given** その名前でパスキーが未登録, **When** 利用者が Mac（localhost）でサインインした状態で「この名前で使うパスキーを追加」を選び、表示されたペアリングの URL（`https://<名前>/pair?token=…`、10分有効）を iPhone で開いて登録の手順を終える, **Then** iPhone からその名前でサインインできる。ペアリングの URL は、一度使うか10分たつと使えなくなる
3. **Given** リモートのアクセスが無効, **When** Tailscale の名前で接続する, **Then** 接続は拒否される
4. **Given** 登録していない名前（別のホスト名や IP アドレス）, **When** その名前で接続する, **Then** 拒否される
5. **Given** リモートからサインインしている, **When** 利用者が Mac の設定の画面でその端末のセッションを無効にする, **Then** その端末は次の操作でサインインを求められる
6. **Given** パスキーが0件、またはペアリングの URL を持たない状態, **When** Tailscale の名前から、パスキーの登録を試みる, **Then** 拒否される（最初のパスキーの登録は Mac のローカルの名前からだけ。ペアリングの URL は、使用済み・期限切れ・存在しないもののいずれも登録できない）

### Edge Cases

- パスキーの登録の途中で中断した（Touch ID を取り消した）とき: 登録は保存されず、もう一度やり直せる
- 回復コードを控えずに画面を閉じたとき: 利用者が「控えた」と確認するまで、サインインのたびに、回復コードを作り直す（古いコードは無効になる）ことを促す（受け入れ条件: 確認の前に閉じて再度サインインすると、作り直しの案内が出る。確認すると出なくなる）
- 回復コードを続けて誤ったとき: 5回続けて誤ると、最後の失敗から15分間受け付けない（ロック中の試行は数えず、ロックは延びない）
- 時計がずれている端末からのサインイン: パスキーの検証は時計に依存しないため影響しない。セッションの期限はサーバーの時計で判断する
- バックアップの最中に帳簿が書き換わったとき: バックアップは、DB ごとにある一時点の一貫した内容を写し、書き換えは妨げない
- バックアップの最中にアプリが終了したとき: 置き場所に書きかけのファイルを残さない（完成したファイルだけが見える）。平文の一時の写しは、次の起動で消される
- 置き場所の空きが足りないとき: 失敗として知らせ、古い世代を勝手に余分には消さない
- 同期フォルダの中のファイルを利用者が手で消したとき: 次のバックアップは、内容が前回と同じでも新しく書く（消えた世代を作り直さないが、最新の内容は必ず置き場所に置く）
- macOS のキーチェーンからパスフレーズが消えたとき（別の Mac に移ったなど）: 自動のバックアップを止めて警告し、設定の画面でパスフレーズの再入力を求める。再入力のときは「今のパスフレーズ」の入力を求めない（キーチェーンが空のときだけ）
- 事業体が1つもないとき: バックアップは取れ、復元もできる（空の帳簿。受け入れ条件: 事業体0件のバックアップを復元すると、事業体0件の帳簿になる）
- 復元の先に、同じ事業体がすでにあるとき: 上書きの確認で事業体ごとの差（仕訳の件数、最後の更新）を示す
- 複数の Mac で同じ同期フォルダを使ったとき: ファイル名に Mac の識別を含め、互いの世代を消さない
- バックアップのファイルの検査（復元の前の確認）で、ファイルが大きすぎるとき: 既存の 413 `FILE_TOO_LARGE` で拒否する

## Requirements *(mandatory)*

### Functional Requirements

**認証**

- **FR-001**: システムは MUST、パスキーが1つも登録されていないとき、帳簿の画面と API を使わせず、パスキーの登録だけを受け付ける。登録は Mac のローカルの名前（`localhost:5173`、`localhost:8787`、`127.0.0.1:8787`）だけで受け付け、Tailscale の名前からは受け付けない
- **FR-002**: システムは MUST、パスキーの登録の完了時に回復コードを生成して一度だけ表示し、利用者の確認を得てから先に進める。回復コードはシステムに元に戻せない形でだけ保存する
- **FR-003**: システムは MUST、サインインしていない要求に対して、帳簿のデータを返すすべての入口（API とファイルの出力〔CSV など〕）を拒否する。拒否しないのは、パスキーの登録・サインイン・回復・ペアリングの手続きに必要な公開の手続き（`GET /api/health`、`GET /api/auth/status`、`/api/auth/` の登録・サインイン・回復・ペアリングの手続きの完全一致の一覧。contracts/http-api.md）と、帳簿のデータを含まない画面の静的ファイル（`index.html`・JS・CSS）だけ
- **FR-004**: システムは MUST、サインインのセッションを、最後の操作から一定時間（既定 8時間）で切る。サインアウトでその端末のセッションを終える
- **FR-005**: 利用者は MUST、サインインした状態で、パスキーを追加・名前の変更・削除できる。削除できないのは `localhost` の最後の1つだけで、Tailscale の名前（ts.net）のパスキーは、すべて削除できる。パスキーを削除したら、そのパスキーで作ったセッションを無効にする。一覧に名前、登録日、最後に使った日、使える接続先の名前を示す
- **FR-006**: 利用者は MUST、回復コードでサインインして新しいパスキーを登録できる。正しい回復コードの入力は、10分間の回復用の一時セッションを作るだけで、回復コードは消費しない（その間は登録をやり直せる）。新しいパスキーの登録が成功したときに、使った回復コードを無効にし、新しい回復コードを一度だけ表示する。5回続けて誤ると、最後の失敗から15分間受け付けない
- **FR-007**: 利用者は MUST、サインインした状態で回復コードを作り直せる（古いコードは無効になる）。回復コードを「控えた」と確認していない間は、サインインのたびに作り直しを促す
- **FR-008**: システムは MUST、認証の出来事（登録、サインイン、失敗、回復、パスキーの削除、セッションの無効化、ペアリングの発行と使用、リモートの設定の変更）を、日時・接続先の名前・端末の情報とともに追記のみの記録に残す（Constitution II）
- **FR-009**: システムは MUST、別の画面や別のサイトから、サインイン済みの利用者になりすまして帳簿を変える要求（クロスサイトの要求）を、要求の本文の形式によらず拒否する

**リモートのアクセス**

- **FR-010**: 利用者は MUST、設定の画面でリモートのアクセスを有効・無効にし、Tailscale の HTTPS の名前を登録できる。既定は無効
- **FR-011**: システムは MUST、Mac のローカルの名前と、登録した Tailscale の名前以外からの接続を拒否する。リモートのアクセスが無効のときは Tailscale の名前も拒否する
- **FR-012**: システムは MUST、パスキーを接続先の名前ごとに管理する。別の接続先の名前（Tailscale の名前）で使うパスキーは、Mac の `localhost` でサインインした状態で発行する、一度だけ使え10分で切れるペアリングのトークン（URL `https://<名前>/pair?token=…`）で、その名前の画面から登録する。トークンの検証に成功すると、その名前の通常のセッションが得られる
- **FR-013**: 利用者は MUST、サインイン中の端末のセッションの一覧（接続先の名前、端末の情報、最後の操作）を見て、個別に無効にできる

**バックアップ**

- **FR-014**: 利用者は MUST、バックアップのパスフレーズ（12文字以上、2回の入力が一致）と置き場所のフォルダを設定できる。設定の前に「パスフレーズを忘れると復元できない」ことへの同意を求める
- **FR-015**: システムは MUST、パスフレーズを Mac のキーチェーンに保管し、アプリのデータの場所やリポジトリには保存しない（Constitution III）。キーチェーンが使えない環境では、パスフレーズを server の起動ごとに一度、設定の画面で入力させ、メモリにだけ保持する。未入力の間は自動のバックアップを止めて警告する
- **FR-016**: システムは MUST、すべての事業体の帳簿と事業体の一覧を1つのファイルにまとめ、パスフレーズから作った鍵で暗号化して置き場所に書く。アプリの設定（`app_settings`）、認証の情報、バックアップの記録は含めない（端末に結びつくため）。ファイルには改ざんや破損を検知できる情報を含める
- **FR-017**: システムは MUST、バックアップの内容を、DB ごとに、ある一時点の一貫した状態にする（事業体の DB どうしの間では、時点が少しずれうる）。バックアップの最中の帳簿の変更を妨げない
- **FR-018**: システムは MUST、置き場所に書きかけのファイルを残さない。完成した時点で初めて、最終の名前のファイルとして現れる
- **FR-019**: システムは MUST、アプリが動いている間、最後の確認（成功、または変更なしの記録）から24時間以上たったら、自動のバックアップの判断を行う。帳簿の内容が前回の成功と同じ、かつ前回の成功のファイルが今の置き場所にあり、かつパスフレーズを変えていないときだけ、ファイルを書かずに「変更なし」と記録する。手動の実行と、設定・パスフレーズの変更の直後の実行では、必ずファイルを書く。利用者はいつでも手動で取れる
- **FR-020**: システムは MUST、バックアップの結果（日時、成功・変更なし・失敗、失敗の理由、ファイルの名前と大きさ）を記録し、設定の画面に示す。最後の確認から48時間以上たった場合、直近の実行が失敗した場合（一度も成功していないが設定が済んでいる場合を含む）、または自動のバックアップに要るパスフレーズが使えない場合は、帳簿の画面の上部に知らせる
- **FR-021**: システムは MUST、新しいバックアップの成功の後、置き場所の、この Mac で作ったファイルのうち、直近30日分の毎日の世代と、それより前の各月の最後の世代（最大7年）を残し、ほかを削除する。ほかの Mac で作ったファイルは消さない
- **FR-022**: システムは MUST、バックアップのファイルを書いた後で、同じパスフレーズで読み戻して壊れていないことを確かめ、確かめられなければ失敗として扱い、最終の名前のファイルを残さない
- **FR-023**: 利用者は MUST、パスフレーズを変えられる。変更の前に今のパスフレーズの入力を求める（キーチェーンが空のときは求めない）。古いバックアップは古いパスフレーズで復元できることを示す

**復元**

- **FR-024**: 利用者は MUST、バックアップのファイルとパスフレーズを指定して復元を始められる。システムは MUST、確定の前に、ファイルの検査（パスフレーズ、破損、版）と、復元される内容の要約（バックアップの日時、作った Mac、事業体ごとの年度と仕訳の件数）を示す。復元先に同じ事業体があれば、事業体ごとの差（仕訳の件数、最後の更新）も示す
- **FR-025**: システムは MUST、帳簿があるデータ場所への復元の前に、今の帳簿のバックアップを取り、その場所を示す
- **FR-026**: システムは MUST、復元を全部か無かで行う。途中で失敗したら、帳簿を復元の前の状態に保ち、展開した一時の場所を消す
- **FR-027**: システムは MUST、アプリの版（registry と事業体の DB のマイグレーションの適用数）が今のアプリと完全に一致するバックアップだけを復元する。一致しなければ（新しくても古くても）拒否する。開発中は帳簿の形式の更新を伴う復元をしない
- **FR-028**: システムは MUST、パスキー・回復コード・セッション・ペアリングのトークン・アプリの設定（`app_settings`）・バックアップの記録を復元しない（端末に結びつくため）。復元した後にパスキーが未登録なら、FR-001 の登録から始める
- **FR-029**: 利用者は MUST、アプリを起動していない状態でも（パスキーが使えない新しい Mac など）、復元を実行できる手段を持つ

### Key Entities *(include if feature involves data)*

- **パスキー**: 登録した認証器の公開鍵の情報、名前、使える接続先の名前、登録日、最後に使った日。秘密の鍵は端末の中にあり、アプリは持たない
- **回復コード**: 元に戻せない形（ハッシュ）だけを保存する。有効・無効、生成日、「控えた」の確認の有無
- **セッション**: 端末ごとのサインインの状態。接続先の名前、作ったパスキー、端末の情報、開始、最後の操作、期限、無効化の状態。回復用の一時セッションは別の種類
- **ペアリングのトークン**: 別の接続先の名前でパスキーを登録するための、一度だけ使える10分のトークン（ハッシュだけを保存）。接続先の名前、発行日時、期限、使用日時
- **認証の記録**: 認証の出来事の追記のみの記録
- **リモートのアクセスの設定**: 有効・無効、Tailscale の HTTPS の名前
- **バックアップの設定**: 置き場所のフォルダ、パスフレーズの保管先（キーチェーンの項目の識別だけ）、この Mac の識別
- **バックアップの記録**: 日時、手動・自動、成功・変更なし・失敗、理由、ファイルの名前と大きさ、内容の要約
- **バックアップのファイル**: 暗号化したアプリのデータ一式。中に、アプリの版、作った Mac、日時、事業体ごとの要約、内容の検査の情報を持つ

## Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-001**: 帳簿のデータを返すすべての入口（API とファイルの出力）について、サインインしていない要求が拒否される（拒否されない入口は0件。公開の手続きと、帳簿のデータを含まない画面の静的ファイルを除く）
- **SC-002**: 利用者は、アプリを開いてからパスキーでサインインを終えるまで10秒以内で済む
- **SC-003**: 合成のデータ（複数の事業体、各数千件の仕訳、取込・決算の登録を含む）でバックアップを取り、空のデータ場所に復元したとき、すべての帳簿の内容が元と完全に一致する（差は0件）
- **SC-004**: 誤ったパスフレーズ、1バイトでも書き換えたファイル、途中で切れたファイルの復元は、すべて復元の前に検知され、帳簿は変わらない
- **SC-005**: 仕訳 数千件/年 × 3年分の帳簿で、手動のバックアップが30秒以内に終わり、その間の event loop の遅延の p99 が 200ms 以下（画面と API の応答が止まらない）
- **SC-006**: パスフレーズを知らない人は、バックアップのファイルから取引先名・金額などの帳簿の内容を読み出せない（ファイルのバイト列に、合成の帳簿の取引先名・摘要と `SQLite format 3` が現れない）
- **SC-007**: 自動のバックアップが2日続けて取られていない状態を、利用者が帳簿の画面で必ず気づける（画面の上部の知らせ）
- **SC-008**: 新しい Mac で、バックアップのファイルとパスフレーズから帳簿を復元し、パスキーを登録して帳簿を使い始めるまでの手順を、利用者が15分以内に終えられる

## Assumptions

- 利用者は本人1人だけ（001 の前提）。利用者の区分や権限は考えない。パスキーは複数登録できるが、すべて同じ本人のもの
- 開発中で、実際の利用者はいない。データの消失や旧版との互換は考慮しない（利用者の指示 2026-10-20）。ただし帳簿の不変条件（Constitution I）は守る
- パスキーは接続先の名前（オリジン）に結びつくため、Mac のローカルの名前と Tailscale の HTTPS の名前で別々に登録する（利用者の確認, 2026-10-20）。Mac のローカルの名前は、パスキーが使える安全な接続の条件を満たす名前を使う
- リモートのアクセスは Tailscale の HTTPS（`tailscale serve`）で提供し、インターネットへの公開はしない（Constitution III、NFR-02）。Tailscale の導入と設定（tailnet、HTTPS の証明書）は利用者が行い、アプリは名前の登録と接続先の検査だけを行う
- バックアップの送り先は、Google Drive for desktop の同期フォルダとする。アプリはフォルダに暗号化したファイルを書くだけで、Google の認証や API は使わない（利用者の確認, 2026-10-20）。同期は Google Drive のアプリに任せる。フォルダは利用者が選ぶので、同期フォルダ以外（外付けのディスクなど）も置き場所にできる
- バックアップは自動（1日1回、変更があるとき）と手動の両方（利用者の確認, 2026-10-20）。自動のバックアップのため、パスフレーズを macOS のキーチェーンに保管する
- バックアップの対象は帳簿のデータ（全事業体と事業体の一覧）。アプリの設定（`app_settings`。バックアップの置き場所、リモートの設定、Mac の識別など）はすべて端末に結びつくため含めない。証憑のファイルは、証憑の機能（FR-08）が入ったときに対象に加える。`work/` などアプリの外のファイルは対象外
- 世代の残し方（毎日30日分、月ごと7年）は、帳簿の保存期間（7年以上、NFR-09）に合わせた既定値とする
- 暗号は、広く使われ検証された方式（パスフレーズからの鍵の導出と、認証つきの暗号）を使う。方式の選定は plan で行う
- 利用者がアプリを使っていない間（Mac がスリープ中、アプリが止まっている間）は、自動のバックアップは取らない。次に動いたときに取る
- 復元の手段（FR-029）は、アプリを開かずに実行できるコマンドとして提供してよい（新しい Mac ではパスキーがまだなく、画面に入れないため）
- 認証とバックアップの設定の画面は、事業体ごとではなくアプリ全体の設定に置く
- 定期的な「復元の試し」（実際に別の場所へ復元して比べる）は、FR-022 の読み戻しの確認と、自動テストでの復元の確認で代える。利用者が手動で行う手順は quickstart に書く
